# 测试与验收

## 1. 自动化命令

在项目根目录执行：

```bash
npm --prefix server test
npm run build
npm run e2e
npm --prefix server audit --omit=dev --registry=https://registry.npmjs.org
npm --prefix client audit --omit=dev --registry=https://registry.npmjs.org
```

- 服务端测试同时运行旧版规则回归、Node 测试套件和机器人完整牌局压力测试。
- `npm run build` 构建服务端、客户端，并同步检查 TypeScript 与生成版客户端文件。
- Playwright 默认启动本地前后端。若机器只有系统 Chrome，可以使用：

```bash
PLAYWRIGHT_CHANNEL=chrome npm run e2e
```

- 两条生产依赖审计命令显式使用 npm 官方 registry，因为部分镜像站没有实现审计接口；当前基线要求服务端和客户端均为 0 个已知生产依赖漏洞。

提交前还应运行：

```bash
git diff --check
```

## 2. 服务端回归矩阵

### 房间与身份

| 场景 | 预期 |
|---|---|
| 单人练习开局 | 一名真人可以开局，余下三席由机器人补齐 |
| 好友房创建与邀请 | 邀请链接携带 roomId，受邀者可以原子领取空座 |
| 同名与重连 | 同房真人同名自动追加可读后缀；断线、刷新或故意提交不同昵称后仍恢复首次入座的稳定名字 |
| 房主管理机器人 | 只有房主可添加、移除机器人或设置 0–100 强度 |
| 等待大厅重连 | 保留期内同 token 恢复原座，过期后释放 |
| 创建后未加入 | HTTP 创建即启动等待房回收计时；宽限内可以完成首次加入，始终无人加入则断开并释放房间 |
| 对局中断线 | 默认 5 秒内保持离线真人且机器人不动作；到期后原座进入托管但昵称不变，标准屏显示“暂由机器人”，极小屏显示“托管中” |
| 断线操作反馈 | 保留牌桌与手牌；顶部明确显示自动恢复，右侧操作坞以“操作已暂停”状态替换所有动作按钮，恢复前没有可点击牌局操作 |
| 对局中重连 | 同 token 恢复原座和真人控制，另一浏览器观察到同一昵称恢复为“真人在线” |
| 同座位多窗口 | 新窗口用同 token 恢复后，服务端通知并关闭旧会话；旧页进入终止状态且不再抢座，新页持续保持同一 seatId |
| 房主断线 | 权限转给座位序号最小的在线真人 |
| 私有手牌 | 每个真人只收到自己的牌和动作候选 |
| 私有状态接口 | 新客户端用 Bearer token，URL 不含凭证，响应为 `no-store`；旧查询参数只作滚动兼容 |
| 房间凭证 | 新凭证匹配 `pt_` 加 48 位十六进制字符、批量生成不重复；旧格式仍可恢复已有座位 |
| 浏览器来源 | 生产模式允许配置来源访问 HTTP、匹配与 WebSocket；未知来源被拒绝，域名后缀伪装不能通过 |
| 调试入口 | 生产环境无条件禁用 `debug_setup`；非生产环境也必须显式开启且只有房主可用，普通玩家不能改写牌局 |
| 管理入口 | 生产模式默认访问不到 `/colyseus`；只有显式启用后才开放诊断页 |
| HTTP 限流 | 创建房间、入口查询和私有状态恢复各有独立预算；超限返回 429、`Retry-After` 和 `rate_limited`，窗口结束后恢复 |
| HTTP 错误说明 | 浏览器可读取限流等待时间并显示中文秒数；5xx 响应中的内部错误详情不会进入玩家界面 |

### 规则主循环

| 场景 | 预期 |
|---|---|
| 集体响应 | 胡、开、碰、过按服务端顺序与优先级裁决 |
| 上家牌本地响应 | 可吃时提供候选；不吃显示“抓”，协议提交 pass |
| 自摸普通牌本地响应 | 可吃或过给下家，过出的牌进入本人弃牌记录 |
| 最高分胡牌拆解 | 同一手牌有多个合法拆解时选择总分较高者 |
| 胡牌响应组成三张 | 按碰展示计分，不按暗坎 |
| 互付文案 | 显示“机器人2 付 金条开：+18分”，名字内部无空格 |

### 特殊牌关键回归

必须使用完整房间流程覆盖四色将、五种金条、不同机器人强度和超时分支：

1. 构造当前玩家手里有绿士、绿象，随后摸到绿将。
2. 前端在集体阶段预选“绿将＋绿士＋绿象”，其他响应者全部过。
3. 服务端进入 `local_draw`，接受预选候选。
4. 断言绿士、绿象从手牌中同时消失，明示区只有一个三张牌组且恰为绿将、绿士、绿象。
5. 断言没有额外的单绿将牌组，并且完成组牌后才进入弃牌确认阶段。

还要覆盖：

- 玩家主动选择单独收下时，明示区新增一个一张牌的将/金条牌组，不写入独立特殊牌区。
- 多个候选存在时等待选择；超时默认单独收下。
- 任意强度机器人都不得把特殊牌弃出或传给下家；胡牌与合法开仍保持原优先级。
- 候选过期、手牌 ID 缺失或目标牌变化时，执行原子失败：手牌、牌池、明示区与流程阶段均不发生部分修改。
- 吃、碰、开共享扣牌路径的普通牌回归仍通过。

## 3. 浏览器回归矩阵

Playwright 至少覆盖 375×667 旋转画布、667×375 iPhone SE 级别横屏和 1280×720 桌面。

| 场景 | 验收点 |
|---|---|
| 页面缩放 | viewport 不含 `maximum-scale` 或 `user-scalable=no`，系统双指缩放不被页面禁止 |
| 顶部控制栏 | 声明、对局、结算均常驻；只含四色牌、设置、退出，且不与座位或弹层重叠 |
| 中央牌桌 | 左牌堆、右待响应牌的组合整体居中；牌堆在待响应牌出现前后位置固定 |
| 牌堆造型 | 八张细长、两头圆、红色牌背重叠，余量数字准确且可访问 |
| 庄家信息 | 只在庄家名字旁出现庄标和定庄牌，不显示抽牌者或重复庄家姓名 |
| 对手手牌数 | 三位对手均显示准确“n张”，摸牌、组牌和弃牌后及时更新 |
| 显示模式 | 我的牌与桌面牌分别切换大字/自适应/长牌，所有对应牌区即时变化，刷新后保留 |
| 座位方向 | 左右玩家及相关动画镜像，自己、对家和服务端行动顺序不变 |
| 设置与回合 | 声明时可调整牌面；面板不透底、关闭按钮不小于 42px；本人需要响应或出牌时面板自动关闭，入口显示“先操作”并禁用 |
| 规则与回合 | 规则速查具有模态语义、Escape 与焦点约束；阅读期间轮到本人时自动关闭，焦点落到可选手牌或合法动作，不能遮挡操作坞 |
| 座位摘要 | 可见界面不重复本人手牌数，不显示牌组/暗坎零值；每个座位的读屏摘要仍包含余牌、牌组、暗坎、连接身份与关键回合状态 |
| 流水信息 | 空流水不显示边框或占位字；有牌时仅显示“出牌者 → 接牌者”，小屏标题字号不小于 12px，且保留完整无障碍说明 |
| 空牌组区域 | 本人和对手没有公开牌组时不显示空边框或“暂无牌组”；首个牌组出现后正常展示，中央牌堆位置保持不变 |
| 紧凑手牌 | 667×375 下牌宽约 40–44px、间距约 2px、字形约 22px 以上，首屏约 9–10 张并可横滑 |
| 手牌翻看 | 手牌溢出时显示左右翻看按钮；首屏左键禁用、右键可用，翻看不改变手牌或触发出牌，触摸横滑仍正常 |
| 牌面可访问性 | 每张牌暴露“颜色＋牌名”，金条读作“金条＋爵位”，待响应状态有文字语义；红底黑字对比度至少 4.5:1，键盘焦点清晰 |
| 确认出牌 | 单击、重复点击和双击只选牌；只有操作坞“出牌”提交，失败后恢复选择 |
| 手牌状态 | 等待、候选和断网阶段全部手牌保持完整对比度；弃牌阶段仅将牌/金条出现“留”标记和“规则保护”读屏说明，且仍清晰可辨 |
| 回合提醒 | 本人可操作时操作坞显示“该你操作了”和剩余秒数；667×375 下说明文字至少 12px 且不越出操作坞；最后 5 秒高对比警示且减少动态偏好有效 |
| 选牌状态 | 选中牌同时有位移、描边和勾选标记，读屏名称以“已选中”结尾；双击仍只改变选择，不直接出牌 |
| 声音与震动 | 新操作窗口只提醒一次；默认响铃加震动，可切为仅响铃或关闭；不支持 Web Audio/振动时不影响操作，标签页标题仍提示“轮到你了” |
| 屏幕常亮 | 默认在声明/对局前台申请 Wake Lock；关闭设置、切后台、结算或退出时释放；API 不存在或拒绝时牌局照常可用 |
| 决策时间 | 生产默认响应/出牌为 30 秒、声明为 45 秒；机器人仍按独立思考延时执行，超时保守动作不变 |
| 特殊牌操作 | 单候选显示“收下”，多候选显示“吃”，动作反馈明确且结果进入明示区 |
| 结算到达顺序 | `ended` 已到但 `round_result` 尚未完整时显示整理中并锁定整桌操作；四家结果到齐后才允许下一局或返回大厅 |
| 小屏结算 | 667×375 真实触屏下本人明细排第一、列表单列、牌宽不小于 32px、牌面字不小于 16px、摘要和明细文字不小于 12px，顶栏与房主操作始终可达 |
| 个人退出 | 打开时默认聚焦“继续游戏”，Tab 焦点留在弹层内，Escape/遮罩/取消均回到退出按钮；确认后停止重连、清凭证并回模式大厅，进行中空座由机器人托管 |
| 好友邀请 | 邀请入口明确写“加入好友房”并说明选座；房主、未入座访客、已入座访客各自看到准确下一步；667×375 首屏可见至少 80px 高的第一排座位；复制成功为绿色状态且链接不含身份凭据；HTTPS/localhost 与普通 HTTP 局域网地址均可复制 |
| 网络中断 | 离线画面保留牌桌与手牌并冻结动作；联网后只建立一个替代 WebSocket，取回原座且凭证不变，再以服务端最新状态覆盖，允许托管期间手牌发生合法变化 |
| 页面刷新 | 有效凭证自动回到原房间和原座，不出现昵称输入；昵称、roomId 与 token 不变 |
| 失效历史房间 | 进入 `closed` 并明确显示已停止自动恢复；等待超过一个退避周期也不新增匹配请求，返回首页后清除房间凭证 |
| 终止性关闭 | 4100–4105 的座位/房间业务关闭和匹配层 522/524 不自动重试；普通断网与服务短暂不可用仍持续恢复 |

每轮视觉调整至少保存定庄完成、普通等待、待响应、选牌待确认、设置展开及两种座位方向截图，检查全局溢出、可读性与控件交叠。

## 4. 人工试玩清单

- 使用真实触屏完成：加入、声明、吃/碰/开/过、选牌确认、设置、退出和结算。
- 在 iPhone SE 尺寸重点检查老年玩家是否能辨认牌字、玩家名、余牌数和动作文字。
- 特殊牌完整走一次“单独收下”和一次“将士象”组合，核对手牌与明示区，而不只观察按钮是否出现。
- 刷新页面确认重连、手牌恢复与显示偏好持久化。
- 在牌局中切断网络后等待数秒再恢复，确认离线期间牌桌不清空、按钮不可操作，联网后无需重新输入昵称或选择房间，并接受托管期间已经推进的服务端最新牌局。
- 对局中直接刷新页面，确认无需点击即可回到原座；再用失效 roomId 验证页面明确停止重试并能返回首页。
- 保持旧页面不关闭，再开一个同源新窗口恢复同一座位；确认旧页显示座位已在其他窗口恢复且保持冻结，新页两秒以上不被旧页抢回。
- 好友房由两名真人和机器人混合完成一局，验证房主转移与个人退出不会让整桌断开。

## 5. 部署后冒烟测试

按 [DEPLOYMENT.md](DEPLOYMENT.md) 更新 iMac 后：

1. 确认容器均为运行状态，服务健康检查返回成功。
2. 普通 Compose 部署访问 `http://imac.tajuren.cn:3000`，确认首页资源、WebSocket 和单人练习可用；只有部署 Traefik/TLS 后才使用无端口 HTTPS 地址。
3. 至少进入一局，检查牌堆造型、对手余牌数、操作坞和特殊牌提示。
4. 创建一个房间但不建立 WebSocket；超过等待房空闲宽限后，确认该 roomId 已不能加入。
5. 对比部署 commit 与本地已验证 commit，避免只重建了旧代码。
