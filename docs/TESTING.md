# 测试与验收

## 1. 自动化命令

在项目根目录执行：

```bash
npm --prefix server test
npm run build
npm run e2e
npm --prefix server audit --omit=dev --registry=https://registry.npmjs.org
npm --prefix client audit --omit=dev --registry=https://registry.npmjs.org
```

- 服务端测试同时运行旧版规则回归、Node 测试套件和机器人完整牌局压力测试。
- Playwright 启动的隔离测试服务提高房间创建限额，并缩短无浏览器连接房间的回收时间，避免串行用例共享来源地址或遗留机器人牌局相互干扰；生产和 Docker 默认值保持不变。结算布局回归在真人完成声明后使用仅测试环境、仅房主可用的确定性胡牌场景，避免依赖随机牌局何时自然结束。
- `npm run build` 构建服务端、客户端，并同步检查 TypeScript 与生成版客户端文件。
- Playwright 默认启动本地前后端。若机器只有系统 Chrome，可以使用：

```bash
PLAYWRIGHT_CHANNEL=chrome npm run e2e
```

- 两条生产依赖审计命令显式使用 npm 官方 registry，因为部分镜像站没有实现审计接口；当前基线要求服务端和客户端均为 0 个已知生产依赖漏洞。

提交前还应运行：

```bash
git diff --check
```

## 2. 服务端回归矩阵

### 房间与身份

| 场景 | 预期 |
|---|---|
| 单人练习开局 | 一名真人可以开局，余下三席由机器人补齐 |
| 机器人昵称 | 从友好昵称池随机选择；同桌机器人之间及与真人之间均不重名，刷新和本局结算期间保持稳定 |
| 机器人身份 | 牌桌、小屏操作提示和结算均有“电脑/机器人”标识，不依赖昵称前缀；真人临时托管仍保留真人昵称 |
| 好友房创建与邀请 | 邀请链接携带 roomId，受邀者可以原子领取空座 |
| 练习房入口隔离 | 并发调用 `/room-id` 必须返回不同房间；每个练习房只允许首位新真人，第二个新 token 被拒绝，而原 token 仍可重连 |
| 同名与重连 | 同房真人同名自动追加可读后缀；断线、刷新或故意提交不同昵称后仍恢复首次入座的稳定名字 |
| 房主管理机器人 | 只有房主可添加、移除机器人；界面用轻松/标准/高手三个大按钮发送 20/50/85，服务端仍安全接受并限制旧客户端的 0–100 强度 |
| 一键补齐电脑 | 好友房房主在固定操作区看到准确的“补齐 N 位电脑”；一次补满所有空座且保留既有成员，机器人昵称唯一、默认标准难度，只广播一次，不自动开局；非房主、满桌和非好友房请求不修改状态 |
| 好友房准备 | 非房主真人入座后显示大字准备按钮和“未准备”；准备后全桌同步“已准备”，所有真人在线且准备前房主开始按钮保持禁用。取消准备、换座、首局计分方式变化和返厅会重新阻止开局；短暂断线保留选择但离线本身仍阻止开局；房主、机器人及牌局中请求不能伪造准备 |
| 未入座访客同步 | 好友邀请访客未选座时能查看大厅但不请求 `/private-state`，控制台不出现未处理 `lobby_presence`；领取座位后立即获得私有状态并恢复周期同步 |
| 等待大厅重连 | 保留期内同 token 恢复原座，过期后释放 |
| 创建后未加入 | HTTP 创建即启动等待房回收计时；宽限内可以完成首次加入，始终无人加入则断开并释放房间 |
| 对局中断线 | 默认 5 秒内保持离线真人且机器人不动作；到期后原座进入托管但昵称不变，标准屏显示“暂由机器人”，极小屏显示“托管中” |
| 断线操作反馈 | 保留牌桌与手牌；顶部明确显示自动恢复，右侧操作坞以“操作已暂停”状态替换所有动作按钮，恢复前没有可点击牌局操作 |
| 对局中重连 | 同 token 恢复原座和真人控制，另一浏览器观察到同一昵称恢复为“真人在线” |
| 同座位多窗口 | 新窗口用同 token 恢复后，服务端通知并关闭旧会话；旧页进入终止状态且不再抢座，新页持续保持同一 seatId |
| 房主断线与退出 | 刷新或意外断线在宽限期内保留房主，及时恢复后权限不变；宽限到期才转给座位序号最小的在线真人。确认主动退出则立即释放/托管并转交，不等待断线宽限 |
| 房主解散好友桌 | 仅好友房等待阶段的房主看到并可操作；二次确认可取消并恢复焦点，确认后所有连接停止恢复、清除房号/token 并回模式选择。普通成员、单人练习和进行中的牌局不能解散整桌 |
| 好友房累计计分 | 默认每局单算；仅房主可在首局前切换。本桌累计时逐局按四个固定座位相加且保持零和，下一局和整桌返厅均保留；首局结算后选择锁定，解散才结束榜单 |
| 私有手牌 | 每个真人只收到自己的牌和动作候选 |
| 私有状态接口 | 新客户端用 Bearer token，URL 不含凭证，响应为 `no-store`；旧查询参数只作滚动兼容 |
| 房间凭证 | 新凭证匹配 `pt_` 加 48 位十六进制字符、批量生成不重复；旧格式仍可恢复已有座位 |
| 浏览器来源 | 生产模式允许配置来源访问 HTTP、匹配与 WebSocket；未知来源被拒绝，域名后缀伪装不能通过 |
| 正式传输地址 | HTTPS 页面默认得到 HTTPS/WSS；只显式配置 HTTPS 或 WSS 任一基础地址时另一项使用相同主机、端口和路径推导；HTTP 试玩仍得到 HTTP/WS，IPv6 本机地址保持合法 |
| 调试入口 | 生产环境无条件禁用 `debug_setup`；非生产环境也必须显式开启且只有房主可用，普通玩家不能改写牌局 |
| 管理入口 | 生产模式默认访问不到 `/colyseus`；只有显式启用后才开放诊断页 |
| HTTP 限流 | 创建房间、入口查询和私有状态恢复各有独立预算；超限返回 429、`Retry-After` 和 `rate_limited`，窗口结束后恢复 |
| HTTP 错误说明 | 浏览器可读取限流等待时间并显示中文秒数；5xx 响应中的内部错误详情不会进入玩家界面 |

### 规则主循环

| 场景 | 预期 |
|---|---|
| 集体响应 | 胡、开、碰、过按服务端顺序与优先级裁决 |
| 上家牌本地响应 | 可吃时提供候选；不吃显示“抓”，协议提交 pass |
| 自摸普通牌本地响应 | 可吃或过给下家，过出的牌进入本人弃牌记录 |
| 最高分胡牌拆解 | 同一手牌有多个合法拆解时选择总分较高者 |
| 胡牌响应组成三张 | 按碰展示计分，不按暗坎 |
| 互付文案 | 显示“阿福（机器人） 付 金条开：+18分”，付款人、`付` 和计分项之间各有一个空格 |

### 特殊牌关键回归

必须使用完整房间流程覆盖四色将、五种金条、不同机器人强度和超时分支：

1. 构造当前玩家手里有绿士、绿象，随后摸到绿将。
2. 前端在集体阶段预选“绿将＋绿士＋绿象”，其他响应者全部过。
3. 服务端进入 `local_draw`，接受预选候选。
4. 断言绿士、绿象从手牌中同时消失，明示区只有一个三张牌组且恰为绿将、绿士、绿象。
5. 断言没有额外的单绿将牌组，并且完成组牌后才进入弃牌确认阶段。

还要覆盖：

- 玩家主动选择单张吃牌时，明示区新增一个一张牌的将/金条牌组，不写入独立特殊牌区。
- 多个候选存在时等待选择；超时默认按单张吃牌处理。
- 任意强度机器人都不得把特殊牌弃出或传给下家；胡牌与合法开仍保持原优先级。
- 候选过期、手牌 ID 缺失或目标牌变化时，执行原子失败：手牌、牌池、明示区与流程阶段均不发生部分修改。
- 吃、碰、开共享扣牌路径的普通牌回归仍通过。

## 3. 浏览器回归矩阵

Playwright 至少覆盖 320×568/375×667 旋转画布、568×320 老旧横屏、667×375 iPhone SE 级别横屏和 1280×720 桌面。

| 场景 | 验收点 |
|---|---|
| 页面缩放 | viewport 不含 `maximum-scale` 或 `user-scalable=no`，系统双指缩放不被页面禁止 |
| 首次入口 | 568×320 昵称页只有一个顶栏规则入口，卡内只有“下一步：选择玩法 / 换个名字”，输入字不小于 18px、按钮字不小于 16px；玩法页只显示两个可用模式且无需滚动，说明字不小于 14px，默认模式获得焦点并有 `aria-pressed`。顶栏显示昵称，“修改昵称”返回后保留输入并聚焦；320×568 自动旋转和 1280×720 同样完整可达 |
| 顶部控制栏 | 声明、对局、结算均常驻；只含四色牌、记录、设置、托管、退出，且不与座位或弹层重叠 |
| 主动托管 | 在线真人开启前二次确认，开启后保留昵称、真人及房主身份，顶部持续高亮“取消托管”，人工牌局动作禁用且机器人继续推进；取消一次点击立即生效。定庄揭晓期间切换不取消动画或提前显示声明；刷新重连保留选择，返回大厅清除；配置机器人不能调用该消息 |
| 开局声明 | 系统推荐完成后主按钮明确显示“开始游戏”和亮鱼/暗坎结果并获得焦点；568×320 显示“上下滑调整 · 手牌可前后翻 · 练习不限时”；同步中按钮禁用且焦点位于弹层，Tab/Shift+Tab 不得逃到背景 |
| 声明手牌翻看 | 568×320 的大字/自适应预览不小于 40×44px、主字不小于 22px，长牌不小于 28×52px、主字不小于 16px；溢出时显示至少 44×34px 的“前翻 / 后翻”按钮，可到达末尾并返回开头，且不改变牌序、亮鱼、暗坎或提交状态 |

| 中央牌桌 | 左牌堆、右待响应牌的组合整体居中；牌堆在待响应牌出现前后位置固定 |
| 紧凑牌桌边界 | 568×320 下牌桌自身 `scrollHeight` 不超过 `clientHeight`，上方、左右、中央和本人明示牌区均在牌桌边界内；同一局切换到 320×568 自动旋转后，牌桌及底部手牌操作行的逻辑高度与横持相差不超过 1px，牌字和按钮不缩小 |
| 牌堆造型 | 八张细长、两头圆、红色牌背重叠，余量数字准确且可访问 |
| 庄家信息与揭晓 | 揭晓前不提前显示庄家边框或常驻牌面；依次呈现红色细长圆头牌背、真实定庄牌与“某某坐庄”，读屏获得同序信息，真实牌面停留足够辨认且整局只创建一轮 81 张发牌飞牌；减少动态偏好下无翻转/飞行。落位后只在唯一庄家名字旁出现庄标和定庄牌，不显示抽牌者或重复庄家姓名；本人坐庄时，庄标和牌面在 568×320、320×568 自动旋转、667×375 和 1280×720 中均完整位于左下角本人信息卡内 |

| 空牌组区域 | 本人和对手没有公开牌组时不显示空边框或“暂无牌组”；首个牌组出现后正常展示，中央牌堆位置保持不变 |
| 紧凑手牌 | 667×375 下牌宽约 40–44px、间距约 2px、字形约 22px 以上，首屏约 9–10 张并可横滑 |
| 老旧小屏 | 568×320 下牌面不小于 40×52px、字形不小于 22px、首屏至少完整显示 8 张；本人信息、手牌和操作坞互不交叠，全部操作按钮至少 40px |
| 手牌翻看 | 手牌溢出时显示“‹ 前翻 / 后翻 ›”文字按钮，小屏至少 44×34px；首屏左键禁用、右键可用，可翻到末尾并返回开头，期间不改变手牌、选择或触发出牌，触摸横滑仍正常 |

| 牌面可访问性 | 每张牌暴露“颜色＋牌名”，金条读作“金条＋爵位”，待响应状态有文字语义；红底黑字对比度至少 4.5:1，键盘焦点清晰 |

| 集体响应预选 | 后位真人在前位尚未响应时立即看见并可点击自己的胡、开、碰、过或本家预吃/抓；操作坞写“现在可以先选”，不显示前位倒计时。提交不清除前位计时、不抢跑游标，最终动作优先级与座次规则不变 |
| 选牌状态 | 选中牌同时有位移、描边和勾选标记，读屏名称以“已选中”结尾；双击仍只改变选择，不直接出牌 |
