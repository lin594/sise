# 游戏规则

本文件描述当前游戏实现采用的权威规则。历史需求与旧版 SRS 只用于追溯；若与本文件冲突，以本文件及其配套测试为准。

## 1. 牌组

全副共 117 张牌：

- 黄、红、绿、白四色，每色均有将、士、象、车、马、炮、卒七种牌，每种四张，共 112 张。
- 金条五张：公、侯、伯、子、男各一张。组牌时五种金条视为同类，但仍保留各自牌面。

“特殊牌”在本文中指四色将与全部金条。特殊牌不得作为普通弃牌主动打出，也不得在自己摸到后传给下家。

## 2. 牌局阶段

一局依次经过：

1. `waiting`：等待大厅、选座和机器人配置。
2. `declaring`：定庄、发牌，玩家声明亮鱼与暗坎。
3. `playing`：服务端权威状态机处理摸牌、响应、组牌与弃牌。
4. `ended`：公布胡牌或流局结果、计分和下一局操作。

座位始终按服务端的固定顺序行动。客户端的“顺时针/逆时针”设置只镜像视觉位置，不改变实际顺序。

### 2.1 定庄与发牌

- 普通开局先随机选一位玩家翻定庄牌；从翻牌者起，黄、红、绿、白分别对应顺位偏移 0、1、2、3，金条按红色计算。
- 四位玩家先各发 20 张；定庄牌随后进入庄家手牌，因此庄家 21 张、其余玩家各 20 张。
- 声明阶段先选择一组或多组“四张同色同字”普通牌，以及四张或五张金条作为鱼；所有候选默认选中，也可以逐组取消。确认后，鱼牌立即从私有手牌移出，各家只看到相应数量的红色牌背；全部玩家完成声明、正式开局时才统一翻开牌面。
- 鱼确认后再选择暗坎数量，可选范围为 `0` 到剩余手牌中可识别的三张组数量，默认选中最高值。选择数字不会立即提交，玩家还需点击“开始游戏”；没有候选鱼或坎时，服务端直接跳过对应步骤。
- 手牌中的所有坎候选始终标记“坎”，标记不随玩家选择的声明数量减少；最终计分按声明数量从合法组合中取对当前结算身份最有利的方案。

## 3. 响应流程

### 3.1 集体响应 `collective`

一张牌成为待响应牌后，服务端向其他座位并发收集合法动作。玩家只能执行服务端给出的动作：

- 胡：满足胡牌拆解时结束本局。
- 开：以手牌中的三张同牌和待响应牌组成四张明示牌组。
- 碰：以手牌中的两张同牌和待响应牌组成三张明示牌组。
- 过：放弃本轮集体响应。

响应牌来自摸牌时，以牌主本人开始的座次确定同级优先顺序；来自弃牌时，以出牌者下家开始。响应提交彼此私密，同一轮先选胡，再在开/碰中按该顺序选最靠前者。无人打断时，好友房和快速桌至少保留一个全局 3 秒隐私窗口；明确打断可立即生效，但必须先等仍可能压过该动作的座位。

将牌和金条不能碰；将牌可以与三张同色将开，金条可以与手中的任意三张金条组成金条开。客户端可以预选随后可能执行的吃牌组合，但真正扣牌只发生在进入本地阶段并再次通过服务端校验之后。

### 3.2 上家牌本地阶段 `local_upper`

集体响应无人取得目标牌后，下家获得专属处理机会：

- 有合法组合时可以吃。
- 不吃时界面显示“抓”；协议仍使用 `pass`，服务端随后摸一张新牌并重新发起集体响应。

原目标牌保留在原出牌者的流水记录中，不重复记入抓牌者弃牌区。中央轮询期间不在流水重复展示。

### 3.3 抓牌的一次中央响应

B 选择抓：从牌堆摸一张放到中央，牌的来源为 `draw`，由 B 开始轮询一圈。

- 胡、开、碰按原优先级裁决。B 可在同一轮提交吃牌选择，只有无人胡、开、碰时才落实；只有吃牌机会也必须询问 B。
- B 不吃普通牌时，自动落到 B→C 流水，直接进入 C 的 `local_upper` 吃／抓阶段，不再次轮询，也不要求 B 再过一次。
- C 吃时移走这一张流水牌；C 不吃或不能吃时旧牌留在流水，C 选择抓后开始下一张牌的响应。
- 将与金条不能过出或进入流水。B 选择合法吃法，超时默认单张吃入；`local_draw` 保留用于特殊牌安全处理和组牌后的弃牌阶段。

吃、碰、开成功后才进入选牌弃牌阶段。弃牌必须先选中普通牌，再点击操作坞中的“出牌”确认；点击或双击牌面本身不会提交。

上家牌无人吃且牌堆只剩 8 张或更少时，本局直接流局，不再继续补摸。玩家完成吃、碰或开后，如果手牌为空或只剩不可弃出的将牌/金条，则无需弃牌，直接按胡牌结束本局。

## 4. 特殊牌的吃牌与组合

### 4.1 将牌

本人摸到将牌时：

- 若手牌中有同色士、象，可以选择“将士象”，三张共同组成明示牌组。
- 也可以选择单张吃牌，将牌作为一张牌的明示牌组展示。
- 手中原有三张同色将可保留为坎，接第四张可开；两张将接响应将只能按单张或合法将士象组合处理，不能生成将坎。

“绿将＋绿士＋绿象”等组合成功时，士、象必须从手牌中同时扣除，三张牌共同进入明示区；绿将不会再被重复放入其他区域。

### 4.2 金条

本人摸到金条时：

- 可以选择单张吃牌，作为一张牌的明示牌组展示。
- 手中原有三张金条可保留为坎，接第四张可开。伯、子接自摸公时按三个单金条组处理，不生成金条坎。

### 4.3 共同约束

- 单张吃入将牌或金条不创建“将牌区”或“金条区”；它们与其他公开组合一样放在明示区，仅牌组大小为一张。
- 有多个合法候选时等待玩家选择，不擅自替换其选择。
- 玩家超时默认按单张吃牌处理；机器人也必须保留特殊牌，不能丢弃或传递。
- 组合执行必须原子化：服务端先按唯一牌 ID 验证池牌和全部手牌；任何一张缺失时，手牌、待响应牌、明示区和流程阶段都不得发生部分修改。
- 吃、碰、开执行失败时不得建立残缺牌组；特殊牌失败分支最终以单张吃牌兜底。

## 5. 合法基础牌组

胡牌拆解和候选计算识别以下基础牌组：

| 牌组 | 构成 | 基础分 |
|---|---|---:|
| 对 | 两张同色同字普通牌 | 0 |
| 车马炮 | 同色车、马、炮各一张 | 1 |
| 将士象 | 同色将、士、象各一张 | 1 |
| 三色卒 | 任意三种颜色的卒各一张 | 1 |
| 四色卒 | 四色卒各一张 | 2 |
| 坎 | 三张同色同字普通牌 | 3 |
| 开 | 四张同色同字普通牌 | 6 |
| 将坎 | 三张同色将 | 3 |
| 将开 | 四张同色将 | 6 |
| 金条坎 | 三张金条 | 9 |
| 金条开 | 四张金条 | 18 |
| 单将组 | 单张将 | 1 |
| 单金条组 | 单张金条 | 3 |

亮鱼按普通鱼 8 分、金条鱼 24 分计。声明坎数是准确配额，不是最低数量：超过配额的普通三张同牌按碰展示，金条没有“金条碰”，未选作金条坎时拆成单金条计胡牌分。若有多种合法分配，胡牌者取胡牌总分最高的方案，非胡牌者取坎、开、鱼互付分最高的方案；例如“三金条坎候选＋两个普通坎候选”只声明 2 坎时，胡牌者采用两个普通坎加三个单金条（15 分），非胡牌者采用金条坎加一个普通坎（互付 12 分）。暗坎可以接胡牌响应牌成为四张开。普通牌作为胡牌响应牌组成的三张同牌按“碰”展示和计分（1 分），不按暗坎处理。响应牌的来源约束在求解阶段参与最优拆解选择，结算使用相同约束和明确牌组类型；已经单吃入明示区的响应牌不能再次加入胡牌拆解。

## 6. 声明与结算

- 发牌结束后，玩家分两步确认鱼与暗坎；机器人和超时座位自动采用各阶段默认值。
- 公开结算展示赢家、胡牌分组、明示牌组、鱼、剩余手牌、弃牌数量和逐项计分。
- 有人胡牌时先执行胡牌收付，再在三名输家之间执行互付；赢家不向输家支付、也不再从互付中收取，赢家的坎、开、鱼已经计入胡牌分。流局时四家都参与互付。
- 互付只计算坎、开、鱼；碰、吃、单将和单金条都不参与互付。多个鱼分别计入互付。
- 付款项目统一显示为“`${付款玩家名} 付 ${计分项}：+N分`”；机器人使用随机友好昵称并带身份标识，例如“阿福（机器人） 付 金条开：+18分”。
- 好友房可在首局前选择“每局单算”或“本桌累计”。累计模式把每局最终得分按固定座位相加，下一局和整桌返回大厅都保留，直到房间解散；首局结算后不可中途改模式。
- 房主可以开始下一局或让整桌返回大厅；个人退出仅离开当前玩家，进行中的空座由机器人托管。

大胡/小胡与下一局定庄仍需进一步规则确认，当前行为记录在 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md)。
