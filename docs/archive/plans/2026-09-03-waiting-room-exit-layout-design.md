# 好友房等待页安全退出与小屏布局设计

## 背景

568×320 实机页面中，好友房等待阶段只有连接状态、规则、邀请、座位和开始按钮，没有可见的个人离房入口。玩家只能使用浏览器返回；这种操作既不清理房间凭证，也可能触发自动恢复，尤其容易让不熟悉浏览器导航的老年玩家误以为无法退出。当前半透明粘性操作栏还会覆盖座位卡，首屏只能看到座位上半部，下一步与房间配置混在一起。

## 方案比较

- 依赖浏览器返回或关闭标签：没有清理凭证的确定语义，重新打开时还可能恢复原房间，不能作为产品流程。
- 在等待阶段复用牌局“记录 / 设置 / 退出”工具栏：可以快速获得退出能力，但记录和牌面设置在尚未开局时没有价值，会增加噪声。
- 为好友房等待页增加独立“离开房间”，同时把页面拆成固定标题、滚动内容、固定下一步三段：入口语义准确，并能彻底消除粘性按钮覆盖座位的问题。

采用第三种。

## 交互与布局

- 好友房等待页标题右侧并列“查看规则”和“离开房间”；按钮始终可见，使用完整中文，不只放图标。
- 点击离开后打开模态确认。默认焦点放在“继续等待”，Enter 不会直接离房；Escape、点击遮罩和取消按钮均关闭弹层，并把焦点还给“离开房间”。
- 房主看到“若还有真人，房主会自动转交；只剩你时房间会关闭”；普通玩家看到“座位会释放并返回模式大厅”。确认后复用 `leaveRoom()`，停止重连、清除房间 token 和 URL 中的房号。
- 等待页改成三段式：标题区固定；模式、邀请和座位放入唯一可滚动内容区；主操作与状态提示固定在底部。底部使用不透明背景并参与布局，绝不覆盖座位卡。
- 568×320 压缩标题、邀请卡与间距，但保持规则、离开、复制、选座和开始按钮的稳定触控面积。座位内容可以纵向滚动，不为塞满四席而缩小文字。
- 单人练习自动开局流程不新增离开按钮，避免短暂等待状态闪现无用控件。

## 验收

- 568×320 好友房首屏同时看见房间标题、规则、离开、邀请信息、固定下一步以及不被遮挡的座位内容。
- 可滚动内容区的边界不与底部操作区相交；滚动到任意位置均不会被半透明渐变覆盖。
- 离开弹层默认聚焦“继续等待”，Tab 与 Shift+Tab 在两个按钮间循环；Escape、遮罩和取消后焦点回到触发按钮。
- 确认离开后返回“游戏模式选择”，`four_room_id`、房间 token 和 URL `roomId` 均清除，不会重新连回旧房。
- 原有单人练习、好友邀请、选座、机器人配置和开局流程不变；375×667 旋转画布、568×320、667×375 与桌面构建回归通过。
