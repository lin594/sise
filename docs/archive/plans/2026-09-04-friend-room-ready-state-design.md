# 好友房准备状态设计

> 已完成并归档；当前行为以权威产品、架构和测试文档为准。

## 目标

好友房坐满后，房主只能在所有在线真人牌友明确表示准备后开局，避免牌友仍在看规则、调整设置或辨认座位时被突然带入牌局。

## 交互

- 房主以“开始好友对局”作为自己的最终确认，不额外显示准备按钮。
- 已入座的非房主真人显示醒目的“我准备好了”；准备后可点击“取消准备”。
- 每个真人座位用文字显示“已准备”或“未准备”，不只依赖颜色。
- 机器人视为始终准备；未入座的访客不能准备。
- 房主界面明确显示尚有几位牌友未准备，开始按钮保持禁用。

## 服务端约束

- `lobbyReady` 是公开的座位状态，只有好友房等待阶段的在线、已入座、非房主真人可以修改自己的值。
- 真人离线仍保留 `lobbyReady`，以免短暂网络波动迫使老人重复操作，但离线本身会阻止开局。
- 真人换座、房主修改首局计分方式、整桌返回大厅时清除准备状态。
- 配置机器人、移除机器人和临时重连不清除其他真人的准备状态。
- 首局开始后不额外修改准备值，因此结算页现有“再来一局”流程保持不变；只有明确返回等待大厅才要求重新准备。

## 兼容性

消息协议增加 `set_lobby_ready { ready: boolean }`，不改变牌局动作协议。旧客户端不会自动满足准备条件，因此部署时前后端应同步更新。
