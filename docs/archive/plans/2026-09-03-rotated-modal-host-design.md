# 旋转画布中的全局弹层设计

## 背景

触屏手机竖持时，应用会把根节点 `.layout` 旋转成横向有效画布。候选、规则和好友房离开确认都位于该根节点内，因此能沿用同一坐标系；牌局退出确认却通过 `Teleport` 挂到 `body`，不会继承根节点旋转。在 320×568 等竖持小屏上，牌桌是横向的，退出弹层仍按竖向物理视口排版，方向、遮罩范围和焦点位置都与当前界面不一致。

## 方案比较

- 继续挂到 `body`，为每个弹层单独复制旋转和安全区计算：需要同步根画布的尺寸、方向、transform origin 与安全区映射，容易在后续设备适配时再次分叉。
- 去掉 `Teleport`，把弹层留在 `GameTools` 内：能够继承旋转，但祖先层的定位、层叠上下文和 overflow 可能裁掉全屏遮罩。
- 保留 `Teleport`，把应用自有全屏弹层挂到 `.layout`：既脱离局部组件的裁切，又自然继承有效画布的旋转、安全区和尺寸。好友房离开确认已经验证了该方式。

采用第三种。邀请链接兜底弹层原本就在 `App` 根布局内，不需要额外迁移；本次只修正仍挂到 `body` 的牌局退出确认，并把规则写入产品与测试文档。

## 交互与实现

- 牌局退出确认继续使用 `Teleport`，目标从 `body` 改为 `.layout`。
- 遮罩覆盖有效游戏画布，弹层在横向牌桌中居中；手机竖持时随 `.layout` 一起旋转，物理屏幕内不得裁切或溢出。
- 默认焦点仍为安全动作“继续游戏”；Tab 与 Shift+Tab 只在两个确认按钮之间循环。
- Escape、点击遮罩或点击“继续游戏”关闭弹层，并把焦点还给顶部“退出”按钮。
- 确认退出仍复用现有个人离房流程，不改变服务端协议、托管、房主转移或重连清理逻辑。

## 验收

- 320×568 触屏竖持进入真实牌局后，根节点有效画布为 568×320，退出遮罩和弹层的边界都完整位于物理视口内。
- 弹层中文字、按钮方向与旋转后的牌桌一致，截图不存在纵横方向冲突。
- 默认焦点、焦点循环、Escape 关闭和焦点恢复均通过自动化测试。
- 568×320 横持、667×375 和桌面行为不回退；完整客户端构建与 Playwright 回归通过。
