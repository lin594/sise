# 浏览器与主屏入口识别设计（已完成）

## 问题

当前页面只有标题，没有站点图标、主屏图标、主题色或 Web App Manifest。浏览器请求 `/favicon.ico` 时还会被单页应用回退成首页 HTML，用户在标签页、历史记录、任务切换和手机主屏上只能看到通用图标。对不熟悉浏览器层级的老年玩家而言，这会增加“刚才玩的游戏在哪里”的识别成本。

正式环境将使用 HTTPS/WSS，适合提供浏览器安装元数据；iMac 仍只是 HTTP/WS 测试环境，不能据此降低正式链路要求。

## 方案比较

1. 只增加一个 favicon：改动最少，能改善标签页，但不能覆盖 iOS 主屏、Android 启动器或启动背景。
2. 增加图标、Manifest 和主题元数据，不注册 Service Worker：覆盖浏览器标签、主屏和支持安装的浏览器，同时每次仍从网络进入实时游戏，不制造离线可用或缓存牌局的错觉。
3. 做完整离线 PWA：安装能力最完整，但需要处理客户端与服务端版本协商、静态资源更新和断网牌局语义；当前实时房间不应在这些机制完成前缓存成“可离线游戏”。

采用方案 2。

## 视觉与入口

- 图标沿用页面顶部招牌：深蓝不透明底色上放置黄、红、绿、白四根细长、两头圆的四色牌轮廓，保持在 Android maskable 安全区内；小尺寸不塞入难辨认的小字。
- 提供可缩放 SVG favicon，以及 180、192、512 像素的不透明 PNG。180 像素用于 Apple 主屏，192/512 像素用于 Manifest；PNG 作为不支持 SVG 图标的兼容后备。
- Manifest 使用中文名称“四色牌”、根路径 `id/start_url/scope`、`standalone` 显示模式，以及与页面首屏一致的深蓝背景和顶栏主题色。不锁定系统方向，继续由现有响应式画布处理横竖屏。
- 页面补充描述、主题色、favicon、Apple Touch Icon 和 Manifest 引用，但不显示安装提示，不要求玩家理解 PWA。

## 缓存与错误处理

- 不注册 Service Worker，不缓存房间 API、WebSocket、身份凭证或进行中的牌局状态；断线恢复继续使用既有房间凭证与服务端快照。
- Nginx 对 Manifest 返回正确类型并允许及时更新；图标和构建资源可长期缓存。明确的静态资源路径不存在时返回 404，不能再回退成首页 HTML。
- 正式 HTTPS/WSS 与 iMac HTTP/WS 配置保持分离；Manifest 本身使用同源相对路径，可在两个环境复用。

## 验收

- 首页 head 中包含唯一 Manifest、主题色、SVG favicon 和 Apple Touch Icon。
- Manifest 字段、语言、颜色、入口范围和 192/512 图标准确；全部 PNG 为声明尺寸、不透明背景，核心图形位于 maskable 安全区。
- 开发服务与 Docker Nginx 都以正确内容类型返回 Manifest、SVG 和 PNG；不存在的静态图标返回 404，而不是首页 HTML。
- 页面、房间创建、WebSocket 和现有 320×568 至 1280×720 布局行为不变。
