# 模式启动慢网反馈设计（已完成）

## 问题

模式大厅中的“开始单人练习”和“创建好友房”会先等待 `/rooms` 建房请求，之后才建立房间连接。请求尚未返回时，页面仍显示可点击的原按钮和普通提示；应用函数虽有 `enteringLobby` 互斥，但玩家看不到点击已经生效。慢网下习惯连续点击的玩家容易误以为按钮坏了，也无法判断该等还是重试。

## 方案比较

1. 只保留函数 guard：不产生重复房间，但没有视觉反馈，问题仍在。
2. 发请求后立刻切到通用全屏加载页：反馈最明显，但会隐藏刚选择的玩法，也会把“建房”和“连接房间”两个阶段混在一起。
3. 在模式大厅原位锁住主按钮并改写按钮、提示；进入 WebSocket 连接阶段后使用对应玩法的专属进度文案。采用此方案，玩家能持续看到自己选择的玩法，失败时也无需重新导航。

## 交互

- 建房或快速配桌开始后，主按钮立即禁用。
- 单人练习显示“正在创建练习房…”，好友同桌显示“正在创建好友房…”，快速配桌显示“正在寻找牌友…”。
- 按钮下方统一提示“请稍候，不用重复点击”；提示使用现有状态区域，不增加遮罩或跳动动画。
- 成功后照常进入房间进度/等待页；失败后按钮恢复原文和可用状态，保留已选玩法与昵称并展示可读错误。
- 快速配桌连接阶段使用“正在寻找牌友”，练习与好友建房后的连接阶段也沿用各自玩法名称，不得闪回“恢复牌局”；主动取消后回到仍保留原选择的玩法页，迟到的连接结果作废。
- 房间内的开局按钮、电脑补位和准备流程不使用这个前置建房忙碌态，行为保持不变。

## 验收

- 延迟 `/rooms` 或 `/matchmake` 时，按钮在一个渲染帧内禁用、显示对应进行中文案和等待提示。
- 连续点击只产生一次请求。
- 429/500/网络失败后恢复按钮，不泄漏内部错误，玩家可以再次提交。
- 568×320 下按钮不位移、不溢出，文字不小于 16px，触控高度不小于 48px。
