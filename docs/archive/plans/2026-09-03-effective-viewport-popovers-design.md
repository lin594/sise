# 旋转画布设置与记录面板适配设计

## 背景与实测

应用在触屏手机竖持时把 `.layout` 旋转为横向有效画布。320×568 设备对应的游戏坐标系是 568×320，但 `GameTools` 的设置和最近操作面板仍直接使用 `100dvw/100dvh`。线上实测设置面板因此得到 515px 的逻辑高度；旋转后的物理宽度达到 501px，左边界为 -180px，远超 320px 屏宽。虽然元素声明了内部滚动，实际面板大半已经被根布局裁掉，底部的提醒、常亮和规则入口无法可靠操作。

面板内的辅助说明约为 11–12px，顶部“记录 / 设置 / 退出”也接近最小字号。对于主要用户为老年人的牌局，这些持续可见或用于恢复迷失状态的文字不应只依赖浏览器自动放大。

## 方案比较

- 在 `GameTools` 中读取 `window.innerWidth/innerHeight` 并通过属性传入：数值精确，但会复制响应式组合函数的状态，并增加 resize 与组件接口维护。
- 给旋转状态单独写一组 `dvw/dvh` 交换规则：改动小，但每个新面板都要记住重复覆盖，容易再次遗漏。
- 由根布局定义 `--effective-viewport-width` 和 `--effective-viewport-height`，旋转时交换其物理轴；所有根布局内的浮层统一引用这两个变量。

采用第三种。它把“当前界面实际使用哪个坐标系”收敛为根布局的一项职责，不增加 JavaScript 状态，也能供后续候选、规则或结算浮层复用。

## 布局与可读性

- 普通方向下有效宽高分别为 `100dvw/100dvh`；竖持自动旋转时交换为 `100dvh/100dvw`。
- 设置与记录面板的宽度不得超过有效宽度，最大高度为有效高度减去顶栏和安全间距；面板始终位于根画布及物理屏幕内。
- 内容超过最大高度时只在面板内部纵向滚动。关闭按钮、各显示模式、方向、提醒、常亮和规则入口必须全部可滚动到并可点击。
- 顶栏按钮文字不小于 13px；设置主要选项不小于 14px，辅助说明与记录时间不小于 13px；关闭按钮保持至少 42px。
- 打开面板后仍聚焦面板本身，Tab/Shift+Tab 不能逃回被遮住的声明或牌桌；Escape 关闭并把焦点还给入口。显示模式和座位方向的持久化逻辑不变。

## 验收

- 在公网 320×568 触屏竖持流程进入声明阶段并打开设置，面板边界完整位于物理视口内，逻辑高度不超过 320px 减顶栏后的可用空间。
- 设置面板 `scrollHeight` 大于 `clientHeight` 时可以滚到最底部；“牌局中屏幕常亮”和“规则速查”完整可见、可聚焦、可点击。
- 同尺寸打开最近操作面板时也位于有效画布内；空状态和有记录状态都不因旋转被裁切。
- 568×320 横持、667×375 与桌面不回退；客户端构建、完整 Playwright 和服务端回归通过。
