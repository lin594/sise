# 老旧小屏牌桌区域完整显示设计

## 背景与证据

线上 568×320 牌局的牌桌可用高度只有约 160px，但紧凑布局仍为上、中、下三行设置约 50px、98px、50px 的硬下限。实测牌桌 `scrollHeight` 为 203px，本人明示牌区的底边比牌桌底边低约 40px；由于牌桌使用 `overflow: hidden`，该区域会被直接裁掉。

同一部 320×568 竖持手机虽会旋转成 568×320 有效画布，手牌操作行却仍按物理 `31dvh` 计算。横持时该行是 108px，竖持自动旋转后变成 120px，进一步把牌桌从约 162px 压到 150px。视觉方向相同，实际空间却不相同。

## 方案选择

- 缩小牌字、玩家名或操作按钮：能维持旧行高，但直接损害老年玩家可读性，不采用。
- 让整张牌桌纵向滚动：会隐藏对手、待响牌或本人明示牌，且依赖不易发现的手势，不采用。
- 按有效画布计算底部操作行，并让牌桌三行共享真实剩余高度：采用。中央行保留足够展示牌堆和待响牌的下限，上下行在剩余空间内等比分配；各牌区内容过多时使用其现有内部滚动，不再把整行挤出牌桌。

## 实现约束

- 在应用根布局定义紧凑手牌操作行变量：普通横持使用 `31dvh`，自动旋转时改用对应的 `31dvw`，两者都保持现有 108–120px 上下限。
- `GameBoard` 只消费这个有效画布变量，不直接读取物理视口方向。
- 紧凑牌桌的上、中、下行改为可收缩比例；中央行保持约 70px 的最低高度，上下行不得再设置会使总高度超过牌桌的硬下限。
- 玩家姓名、机器人标识、余牌数、牌面和操作按钮尺寸不缩小；牌堆与待响牌的中心轴和固定位置不变。
- 对手牌组、流水和本人明示牌继续在各自区域内部滚动；牌桌自身不出现纵向滚动，也不裁切整个网格行。

## 验收

- 568×320 正式牌局中，牌桌 `scrollHeight` 不超过 `clientHeight`，上方玩家、左右玩家、中央区和本人明示牌区的边界全部位于牌桌内。
- 同一局从 568×320 切换为 320×568 自动旋转后，牌桌逻辑高度、底部本人区域高度相差不超过 1px。
- 两种方向下均保留至少八张完整可见手牌、40×52px 大字牌、22px 主字和至少 40px 的操作按钮。
- 本人存在多个明示牌组时只在本人明示区内部滚动，不覆盖手牌、操作坞或中央牌堆。
- 667×375、375×667 和桌面布局保持原有信息结构与操作行为，牌局协议和服务器状态不变。
