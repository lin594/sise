# 全局响应期间确认吃牌

上家出牌的实际下家在全局响应期间可看到延后的“吃”，无论是否同时可碰。接口复用 `AvailableAction.deferred`，不增加协议字段；抓出的中央牌不新增此预览。

用户选择组合并点击“吃”后，客户端记录轮次、目标牌、候选与全局决策键，发送一次全局放弃。界面显示“已选择吃，等待其他玩家响应”。其他玩家的胡、开、碰优先级不变。

无人截取后，客户端等待新的本人 `local_upper` 决策和私有手牌同步，再提交同一候选一次。目标、轮次、候选失效、开启托管或断网均清除意图；重连不会重放未完成的意图。没有点击确认的唯一候选只预选，不提交。

延后吃不触发 10 秒窗口。公开倒计时仍为三秒；实际共享窗口沿用在线、非托管真人可胡／开／碰时十秒，否则多人局三秒的规则。

验证包括服务端下家范围、吃碰并存、已提交后的不可重复响应、三秒窗口及抓牌预览排除；浏览器双真人确认吃、其他玩家放弃／碰、单独可吃、私有手牌延迟、断线后重新确认和只消费一次。已有四人竞争、超时与恢复回归继续运行。
