# 产品与体验规范

## 1. 当前产品范围

当前正式支持：

- 单人练习：每次进入都创建独立房间，只允许一名真人，空座由机器人补足；陌生访客不能通过旧链接串入。
- 快速配桌：一键寻找其他真人，短暂等待后由标准电脑补足空座并自动开始；玩家不会因在线人数不足一直空等。
- 好友同桌：创建私有房、复制邀请链接、自由选座，房主可以添加和调节机器人。
- 本机临时档案：无需注册或密码，跨房保留已玩局数和胡牌局数；权威结算由服务端累计。
- 活动牌局恢复：页面刷新、短暂断网或服务容器重建后，使用本机房间凭证恢复原房号、座位、手牌和未完成决定。
- 可识别浏览器入口：标签页、任务切换和手机主屏使用与顶部招牌一致的四色牌图标；正式 HTTPS 环境可添加到主屏，但不宣称离线可玩。
- 声明、完整牌局、胡牌/流局结算、下一局、整桌返回大厅和个人退出。

尚未作为可用功能交付：正式账号注册登录、跨设备找回、公开房间列表、排行榜、长期牌谱/历史回放和多服务实例间的活动房迁移。正式玩家入口不展示这些尚不能完成的操作；规划信息只留在文档中，不能让玩家走进死路。

首次进入保留两个单一任务页面：先确认系统预填且可编辑的临时昵称，再选择“单人练习”“快速配桌”或“好友同桌”。昵称页当场说明“不用注册、不用密码、这台设备会记住昵称”，避免把临时身份误解成账号申请；主按钮明确写“下一步：选择玩法”，规则只在全局顶栏出现一次。568×320 下输入字不小于 18px、标签不小于 15px、两个操作按钮文字不小于 16px，顶部“查看规则 / 修改昵称”文字不小于 14px。玩法页持续显示当前昵称和“修改昵称”，返回修改时保留名字并把焦点放回输入框；三张可用模式卡必须同时完整可达，单人练习标为新手推荐，选择状态同时使用文字、边框和 `aria-pressed`。好友邀请链接仍直接显示“加入好友房”，不经过普通玩法选择，并同样说明无需注册。提交后使用“正在进入朋友的牌桌”进度页，不能误写成恢复旧牌局；同一帧连续回车或点击只允许一条加入流程，失败后回到原邀请昵称页并保留昵称与邀请地址，便于直接重试。

玩法启动遇到慢网时必须立即给出稳定反馈。创建单人练习或好友房期间，模式卡和主按钮统一锁定，按钮分别显示“正在创建练习房…”或“正在创建好友房…”，并提示“请稍候，不用重复点击”；快速配桌进入独立的“正在寻找牌友”连接页。连续点击只能产生一次请求，失败后恢复原模式、昵称和可操作按钮；主动取消快速配桌应返回原玩法选择，而不是昵称首页。

房间建立后的开局同样需要权威回执前的可见提交态。练习自动开局、好友房主开始和快速配桌立即补位第一次成功发送后，开始按钮立即锁定并分别显示“正在开始练习…”“正在开始好友对局…”或“正在补齐并开局…”，提示“开局请求已发送，请稍候”；连续点击只发送一次。收到声明阶段或大厅错误后解除提交态，8 秒仍无权威阶段变化则恢复原按钮并明确提示再次点击，不能让玩家永久等待或盲目连点。

浏览器图标使用深蓝不透明底色和黄、红、绿、白四根细长两头圆的牌形，不使用普通扑克牌造型。页面提供 SVG favicon、传统 ICO、Apple Touch Icon 和 192/512 像素 Manifest 图标；主屏启动背景与页面首屏均为深蓝，避免加载时白屏闪烁。旧版 iOS 不完整支持 Manifest 时，通过 Apple standalone 元数据仍使用“四色牌”名称和不透底的黑色状态栏启动。Manifest 只描述同源入口和独立窗口外观，不锁定方向、不注册离线 Service Worker，也不缓存身份凭证或实时牌局。明确的图标或 Manifest 路径缺失时必须返回 404，不能用首页 HTML 冒充成功响应。

浏览器首次使用时生成与房间凭证分离的高熵档案凭证。模式大厅只在服务可用时显示“本机临时档案 · 已玩 N 局 · 胡 N 局”，零局使用“还没有完成牌局”；加载或服务失败不能阻止进入游戏，也不显示跳动的占位骨架。摘要是带“查看”提示的按钮，在 568×320 与自动旋转画布中触控高度不小于 40px、可见文字不小于 14px，同时不能挤掉三种玩法；详情用大字展示昵称、已玩局数、胡牌局数、胡牌率和累计总分。零局胡牌率显示“—”，不把没有样本误写成 0%。详情只提供安全关闭，Escape、遮罩和按钮关闭后都把焦点还给摘要。凭证不得进入地址、邀请链接、公开牌桌、详情 DOM 或日志。页面必须明确这是当前浏览器上的临时档案：清除浏览器数据后无法找回，也不能被表述为正式账号；未来正式账号应提供显式绑定迁移，而不是静默合并。服务端档案存储短暂中断不能阻止结算或悄悄永久切换到易失内存；中断期间的唯一结算和最后昵称应暂存在进程内，存储恢复后自动幂等补写。

浏览器隐私设置、内嵌环境或存储故障可能禁止本地保存。此时入口仍需生成可编辑昵称并允许玩家在当前页面完成游戏，但必须把“这台设备会记住昵称”替换为“本次仍可正常游戏；刷新或关闭页面后可能无法回到牌局”，同时隐藏本机档案摘要。昵称、显示偏好、档案凭证和房间凭证都使用页面内存兜底；任何存储异常不得造成白屏、按钮失效或泄漏内部错误。无法写入长期存储时，不承诺刷新或关闭后的找回能力。

快速配桌进入后按 A→B→C→D 的第一个空位自动落座，不显示选座、邀请、准备、计分方式或机器人难度。等待页只突出真人数量和服务端权威倒计时：首位玩家进入后默认等待 12 秒，四名真人坐满后缩短为约 1 秒；普通加入和刷新都不能重置倒计时。首位玩家可用“电脑补位，立即开始”跳过剩余等待，其他人只看到自动开始状态。保留中的断线真人座位不得被第五人挤占；玩家恢复后沿用原截止时间，仍未恢复时暂停开局。匹配身份只保存在本机，不生成可分享房间 URL。

快速桌结算不提供“下一局（房主）”或“全桌返回大厅”。每名真人都看到“再来一局（重新配桌）”，点击后只让本人离开旧桌并寻找新的开放桌，旧桌其他玩家继续查看结算。快速桌固定每局单算；连接或重配失败时返回模式大厅并显示可重试说明，不静默降级为单人练习。

单人练习结算只提供“再练一局”和“返回玩法选择”。前者在当前练习桌开始新局，后者按个人离房流程停止重连、清除当前房间凭证，再回到同时包含“单人练习”“快速配桌”“好友同桌”的完整玩法页；不能返回一个只能再次开始练习的伪大厅。

好友邀请链接打开后，昵称页必须直接说明这是好友房邀请、下一步需要选择空座位，主按钮使用“加入好友房”，不能再显示只适用于单人练习的介绍。好友房内根据状态给出单一下一步：未入座时提示选空座，普通玩家入座后提示等待房主，房主提示分享链接并在四席就绪后开始。极小屏压缩邀请说明，优先让空座位进入首屏。

好友房始终把“复制邀请链接”放在邀请操作首位，只复制带 roomId 的完整 URL，不调用系统分享。支持 Web Share API 时另外显示“邀请牌友”，只分享一段含邀请说明、换行和完整 URL 的纯文本，不单独传入 title、url 或 files，减少 iOS Edge 到微信时把 URL 转为附件的兼容问题；实际粘贴表现仍需真机验证。玩家取消分享时保持原房间不变，不自动复制且不显示错误；其他分享失败自动降级为复制链接。复制和分享使用独立的忙碌文案，处理期间邀请按钮禁止重复触发，结束后焦点回到实际入口。复制成功使用短暂的绿色提示，不得伪装成红色错误；普通 HTTP 局域网试玩没有现代 Clipboard API 时也必须提供兼容复制。若浏览器连兼容复制也拒绝，显示站内大字链接弹层并自动全选，支持长按复制、焦点约束和安全关闭，不调用不可控的系统 `prompt`，也不要求玩家理解安全上下文限制。

邀请按钮在小屏可换行，必须保持完整文字与座位可见性。好友在身边时还可打开“出示二维码”，由另一台手机直接扫码加入；二维码必须在本机生成，只包含无凭据的加入地址和房间号，在低高度横屏及自动旋转画布内保持足够尺寸和完整关闭按钮，生成失败时回退为自动全选的本地邀请链接。

好友房等待页采用固定标题、独立滚动内容和固定下一步三段式布局；底部操作必须参与布局且使用不透明背景，不能覆盖座位。等待阶段始终提供完整文字“离开房间”，二次确认默认聚焦“继续等待”，Escape、遮罩和取消都回到原按钮。确认后清除房间凭证并返回模式大厅；房主还要明确知道房主会转交或空房会关闭。568×320 首屏至少完整呈现房间控制、邀请、固定下一步和 80px 高的首排座位内容。

未入座访客选择空位或已入座玩家换座后，在权威座位变化到达前只保留一个选座请求：目标按钮显示“正在入座…”或“正在换座…”，全部其他空座按钮暂时锁定，并明确写出正在确认的 A/B/C/D 座位。连续点击不同空位不能让玩家意外移动到第二个位置；大厅错误、断线或 8 秒无确认后恢复选择并提示重试。一次入座完成后仍可主动换到另一个空位。

房主配置机器人时使用“轻松 / 标准 / 高手”三个清楚的大按钮，不要求拖动精细滑杆。默认“标准”；三档分别对应服务端强度 20、50、85。旧客户端和服务端仍保留 0–100 数值兼容，界面按 `<35`、`35–69`、`≥70` 映射回三档显示。

好友房房主缺人时，固定操作区显示“补齐 N 位电脑”，一次用标准难度机器人填满全部空座；已有真人、已有机器人和座位位置不得变化，补齐后也不得自动开局。等待房标题直接说明“还差 N 位即可开局”“四席已就绪”“请先选择座位”或“等待牌友重新上线”，避免只显示无行动含义的“房间准备中”。逐席添加、移除和调节难度仍然保留。

好友房在首局开始前由房主选择“每局单算”或“本桌累计”，默认每局单算。本桌累计按固定座位保存每局结算分并持续到房间解散；整桌返回大厅或开始下一局都不能清零。首局完成后计分方式锁定，等待大厅展示四席累计榜，结算页同时突出“本局”和“本桌累计”，避免老年玩家把两种数字混为一谈。当前累计只绑定本桌座位和房间凭证；完整账号体系上线后再关联长期账号，不把现有临时昵称伪装成账号。

好友房的非房主真人入座后，固定下一步改为大字“我准备好了”，准备后可“取消准备”；每个非房主真人座位同时用文字显示“已准备 / 未准备”，不能只依赖颜色。机器人视为已准备，房主按“开始好友对局”即代表自己的最终确认。服务端在四席坐满、所有真人在线且非房主真人均明确准备前拒绝开局。短暂断线保留原准备选择，但离线本身仍阻止开局；换座、房主修改首局计分方式或整桌返回等待大厅后重新确认。

准备和取消准备都必须等待权威座位状态：发送后按钮分别显示“正在准备…”或“正在取消准备…”并锁定，提示“准备状态已发送，请稍候”。连续点击只能发送第一个目标值，不能因第一次状态快速到达而让第二次触摸立即反向操作；大厅错误、断线或 8 秒无确认后恢复按钮并提示重试。界面不提前把座位乐观标成已准备。

结算后若好友桌仍有其他真人，房主点击“下一局”必须先看到全桌影响确认，说明其他牌友会立即离开结算；默认焦点放在“继续看结算”，Escape、遮罩和取消都返回原按钮。单人练习和只有房主加机器人的好友桌直接开始下一局，避免无意义的重复确认。

## 2. 核心体验原则

主要受众包含老年玩家，因此产品优先保证：

- 牌字清楚、主要动作稳定可点，不能为了在一屏塞下全部手牌而无限缩小。
- 小尺寸手机也能完成全部流程，不依赖双击、精细拖拽或隐藏手势。
- 旧版手机浏览器不支持 `dvh/dvw` 时仍须获得完整画布；物理视口由运行时像素变量统一提供，传统 `vh/vw` 只作脚本加载前的后备，不能让自动旋转、键盘或地址栏变化裁掉操作区。
- 不禁止浏览器和系统的页面缩放；低视力玩家始终可以使用双指放大，按钮自身仍使用稳定的单击语义防止误触。
- 牌桌只保留影响当前决策的信息；同一信息不在顶部、中央和座位处重复出现。
- 设置和退出始终可见，但与牌局内容有明确边界。
- 所有关键状态既有视觉反馈，也有易懂文字，不能只靠颜色区分。
- 每张牌的读屏名称必须包含颜色和传统牌面字；金条还要明确读作“金条公/侯/伯/子/男”，待响应牌不能只靠星号表达。
- 网络短暂中断不能清空牌桌或手牌，玩家应能明确知道系统仍在自动恢复。
- 同一个服务端权威状态只能呈现一次；重复快照、迟到补丁和仅含私有信息的同版本消息不得让牌桌闪回、流水换位或重播已经发生的动画。
- 单人练习中的在线真人声明、响应和出牌不限时，并明确显示“练习不限时”；机器人和断线后的托管仍按计时推进，避免无人牌局停滞。
- 568×320 等老旧小屏中，入口提示、声明结果摘要、倒计时/“练习不限时”、本人非零牌组/暗坎摘要和异常提示均不小于 13px；只有声明步骤编号等纯装饰文字可以更小。牌堆单位保持完整行高，不能为了节省几个像素裁掉字形。
- 好友房默认给真人 30 秒完成响应或出牌、45 秒完成开局声明；倒计时用于建立预期而非催促。每名真人在自己的每个决策窗口都可主动增加一次 20 秒，按钮紧邻倒计时且使用完整中文；旧窗口的迟到请求不得延长下一次决策。
- 集体待响不要求真人逐个干等。尚未轮询到但已有胡、开、碰或本家吃/抓选择的真人可以立即先选；界面明确写“现在可以先选”，提交后由服务端按原座次和动作优先级统一结算。预选阶段不显示别人的倒计时，也不能替别人加时。
- 机器人集体待响只保留足以看清状态变化的极短停顿；机器人吃牌、抓牌和出牌保持短而可感知的思考时间。好友房和快速桌中的在线真人即使没有可用响应，也保留固定 3 秒待响窗口，且提前点“过”不能缩短该窗口；后位真人的私下预选到达其座位时也保留同样窗口，避免零延迟跳过泄露暗牌能力或预选状态。单人练习、机器人、托管座位以及全员响应完成后的本地阶段仍走快速路径。
- 开局声明由系统预选推荐方案，主按钮使用“无需声明，开始游戏”或“开始游戏 · 亮鱼 N 组 · 暗坎 N 个”，不能只写含义模糊的“确认”。极小屏常驻“上下滑调整 · 手牌可前后翻”提示；手牌到齐后焦点落到开始按钮，手牌同步中或提交完成后聚焦声明弹层，Tab 始终留在弹层内。
- 新的真人操作窗口开始时，只发出一次温和提醒；默认响铃加震动，可改为仅响铃或完全关闭。另有默认关闭的“语音提示轮到我”，开启后只在本人的新决策窗口用一句中文读出实际下一步，弃牌时明确说明先选牌再确认，不能持续解说别人操作。浏览器不支持或尚未允许音频、振动、语音时静默降级并在设置中说明，视觉提示始终保留。

触控尺寸根据有效画布自适应，不设全局固定 48px 的硬指标；验收标准是手指能稳定点击、控件互不遮挡且全部可达。

## 3. 顶部控制区

声明、对局和结算阶段均保留独立顶栏：

- 左侧展示简洁“四色牌”招牌。
- 右侧展示带文字的“记录”“设置”“托管”和“退出”；“记录”用于回看本局最近操作，不承载规则状态或开发信息。老旧小屏上的按钮文字不得小于 14px。
- 顶栏适配安全区，只承载全局控制和连接状态，不显示庄家、回合、牌堆或待响应等牌局信息。
- 牌桌和弹层从顶栏下方开始，不得与顶栏相交。
- 设置和记录面板从顶栏下方展开，尺寸使用旋转后的有效画布而不是物理屏幕的原始宽高；小屏内容过多时只在面板内部滚动。主要选项文字不小于 14px，辅助说明不小于 13px，最底部入口必须能够滚动到并操作。

退出是个人退出：确认后停止自动重连、清除当前房间凭证、离开连接并返回模式大厅。确认弹层默认聚焦“继续游戏”，焦点不得逃到背景，Escape 或点击遮罩只能取消并把焦点还给退出按钮，避免误按回车离桌。所有应用自有的全屏弹层必须使用有效游戏画布的坐标系；手机竖持且牌桌自动旋转时，遮罩、文字和按钮随牌桌一起旋转并完整留在物理屏幕内。结算页的“下一局”和“整桌返回大厅”必须标注为房主操作，避免混淆。

好友房等待大厅另为房主提供“解散房间”，与个人“离开房间”并列但文案、颜色和二次确认必须明确区分。确认解散后整桌所有成员立即停止重连、清除本房间凭证并返回模式选择；普通成员看不到该入口，对局进行中不能解散整桌。

“托管”只把当前真人座位的操作临时交给机器人，不改变昵称、真人身份或房主身份。开启前必须二次确认；开启后入口持续高亮为“取消托管”，手牌和操作坞停止接受人工提交并明确说明机器人正在代打；取消无需二次确认，点击一次立即取回控制。定庄揭晓期间切换托管不得中断动画或提前弹出声明界面，进入真正声明窗口后由机器人自动提交。刷新或短暂断线后保留玩家主动选择，返回等待大厅时清除。

## 4. 网络状态与恢复

- 大厅显示简洁“网络正常”，不向普通玩家暴露座位 ID、房主内部 ID 或 token。
- 牌局连接正常时不额外占用桌面空间；断线、重试和刚恢复时，在顶部控制栏显示高对比文字状态。老旧小屏的状态主文字不小于 14px；需要手动重试时，按钮不小于 36px 高、14px 字。空间不足可以隐藏辅助说明，但不能缩小、截断或隐藏主状态，也不能覆盖招牌和牌局控制。
- 离线时提示“联网后自动恢复”；网络或服务短暂异常时说明系统仍会继续，并提供“立即重试”。
- 断线期间保留最后看到的牌桌与手牌，但禁用所有牌局动作；恢复后以服务端权威状态覆盖本地画面。
- 断线、自动重试和重连期间，右侧操作坞必须用明确的“操作已暂停”恢复状态替换灰色动作按钮，说明无需反复点击；极小屏仍要完整显示“自动恢复”含义，不能只依赖顶部状态点。
- 刷新页面或手机系统回收页面后，只要本机房间凭证仍有效，就直接回到原座，不要求重新输入昵称或再次选择模式。
- 已进入房间、牌局或恢复流程时，手机系统返回键与浏览器边缘返回手势先留在当前页面：已有设置、记录或规则层时只关闭最上层，否则复用当前阶段的离房确认。取消后继续原局；确认后停止重连、清除凭证并返回大厅。页面内主动退出或房间端结束也要同步释放这层保护并清理旧房间查询参数；刷新不拦截，继续使用原座恢复。
- 自动恢复尚未成功时显示独立恢复页，并始终提供“放弃恢复，返回首页”。恢复成功后，顶部至少保留 6 秒“已恢复 · 请核对手牌”，并在空间允许时说明离线期间系统可能代为操作；提示不得遮挡或抢走当前操作。若房间已经结束/回收、原座失效、玩家被移出或同一座位已在其他窗口恢复，应立即停止自动重试，清楚说明原因并只保留“返回首页”；不能把玩家困在无意义的恢复循环中。
- 同一座位被新窗口接管后，旧窗口保留最后画面供辨认，但所有动作冻结并显示“已停止自动恢复”；新窗口必须持续保持真人控制，两个页面不能来回抢占。
- 创建房间等 HTTP 操作被限流时，应显示服务端给出的安全中文原因和准确等待秒数；服务异常只显示可操作的通用提示，不能把内部路径或异常详情暴露给玩家。
- 轻量身份以昵称和房间凭证为主，不要求老年玩家先注册账号或记忆密码。账号体系未交付前，不得把房间 token 描述成正式登录。
- 真人首次入座后昵称在本房间内保持稳定；同名真人自动显示“昵称（2）”等清晰后缀，避免流水、座位和结算无法辨认。类似“机器人2”的旧式机器人昵称由真人使用时仍需标明“（玩家）”。
- 预先配置的机器人从友好昵称池中随机取名，同一牌桌内不得重名或与真人重名；昵称本身不要求带“机器人”字样。牌桌座位、操作提示和结算必须另行显示清晰的“电脑”或“机器人”身份标识，小屏也不得隐藏该标识。
- 紧凑牌桌的左右座位把姓名独立放在首行，电脑身份、余牌数和庄家信息放在下一行并可自然换行，不能用缩小姓名或横向滚动换空间。本人姓名与独立“你”标识分开，常见三至四字昵称应完整可见。
- 真人断线后先保留默认 5 秒重连宽限，显示“真人离线”且不允许机器人代操作；到期后标准屏显示“暂由机器人”，极小屏显示醒目的“托管中”。全程保留真人昵称，不得改名为带 `[BOT]` 的名字，也不得套用预先配置机器人的随机昵称。
- 好友房房主刷新或意外断线时，在重连/座位保留期内继续保有房主身份；及时恢复后不能因为一次网络波动丢失开局和结算权限。只有保留期结束仍未恢复时才转交给座位顺序最靠前的在线真人。玩家在确认弹层中主动退出则立即释放等待座位或启用牌局托管，并立即转交房主，不让其他牌友无意义等待。
- 真人重新连接后恢复“真人在线”状态，并明确提示托管期间的最新牌局已经同步。

## 5. 牌面显示设置

玩家可以分别设置“我的牌”和“桌面牌”：

| 模式 | 表现 |
|---|---|
| 大字 | 单个正向大字，优先可读性 |
| 自适应 | 小屏使用大字，标准桌面使用长牌 |
| 长牌 | 传统上下双字的细长牌面 |

两类设置默认均为“自适应”，并保存在浏览器本地：

- “我的牌”覆盖声明预览、实时手牌、候选中的本人手牌和本人结算手牌。
- “桌面牌”覆盖待响应牌、定庄牌、所有玩家公开牌组、流水、亮鱼、动画和结算中的其他牌。
- 旧版 `simple/full` 偏好迁移为桌面牌“大字/长牌”，我的牌保持自适应。
- 长牌在桌面大屏上使用接近大字牌的可读字号；周边玩家的同一明示牌组在大字、自适应和长牌三种模式下都采用轻微错位覆盖来节省横向空间，但每张牌的主字必须完整可见。自己的明示区保留更宽松的逐张查看空间。待响应或新收入牌只用高对比边框强调，不再用星形文字覆盖牌面。

好友房等待页把四席明确标成 A位（1号）、B位（2号）、C位（3号）、D位（4号）；进入牌桌后必须继续严格使用 A→B→C→D 的固定关系，不能因玩家加入、换座或机器人补位顺序改变上下家。设置还提供顺时针与逆时针座位方向。切换只镜像左右玩家及其牌组、流水、动作反馈、回合指向和飞牌动画；自己和对家不动，服务器座位号与实际出牌顺序不变。默认保持逆时针显示。操作提醒与这些显示偏好一并保存在本机；轮到本人时页面标题同步改为“轮到你了”，便于从浏览器标签或任务切换界面识别，操作窗口结束后恢复。

声明预览与实时手牌都必须优先保证“我的牌”可辨认。568×320 等老旧小屏中的大字/自适应声明牌面不小于 40×44px、主字不小于 22px；长牌不小于 28×52px、主字不小于 16px。声明手牌保持单行横滑，发生溢出时同时提供至少 44×36px、文字不小于 13px 的“前翻 / 后翻”按钮，不能要求玩家自行发现隐藏手势；两个按钮之间显示“1–9 / 18”形式的实际可见牌号范围，帮助玩家确认是否已经看完。翻看不会改变亮鱼、暗坎或提交状态。

“牌局中屏幕常亮”默认开启，只在已连接的声明和正式对局阶段申请屏幕常亮；切到后台、进入结算、退出房间或关闭设置时立即释放。该能力属于渐进增强，浏览器或非安全来源不支持时不得影响游戏；设置必须明确标成“不可用”并禁用开关，不能让玩家误以为屏幕已经保持常亮。本机偏好仍保留，进入支持该能力的正式 HTTPS 环境后自动生效。

设置提供“减少动态效果”，默认关闭并保存在本机。开启后停止飞牌、翻转、循环闪动和顺滑滚动，但定庄牌、操作反馈与错误说明仍保留足够阅读时间，服务端思考与响应顺序不变。操作系统已经要求减少动态时，即使游戏内开关关闭也必须采用静态表现；不能要求玩家先找到系统设置。

“语音提示轮到我”与响铃/震动分别设置并保存在本机。每个新的服务端决策键最多播报一次，普通状态同步、动画更新或操作回执不得重复；进入新决策前取消尚未结束的旧播报。语音使用中文和略慢语速，不改变倒计时、动作优先级或操作坞文字。Speech Synthesis 不可用时入口显示“不可用”，不得抛错或假装已经开启。

设置面板必须使用不透底的高对比背景，避免牌桌文字穿透干扰阅读；关闭按钮在极小屏仍需保留稳定触控面积。内容超出小屏高度时，在底部持续显示“下滑查看更多设置”，到达最后一项后自动消失，不能只依赖默认滚动条暗示。打开后焦点进入面板，Tab 不得逃到背景；Escape、关闭按钮或点击面板外均可关闭，并把焦点还给设置按钮。声明、响应和出牌期间均允许打开设置，打开面板不暂停服务端计时，也不得清除已选手牌或候选。面板固定显示“轮到你操作”：好友局显示准确剩余时间，练习局显示“练习不限时”，并提供“返回出牌”或“返回操作”按钮；关闭后焦点回到已选牌、出牌确认或首个合法动作。

规则速查使用可通过 Escape 关闭、焦点不会逃到背景的模态窗口。568×320 等紧凑画布使用单列纵向阅读，正文不小于 15px、关键标签不小于 14px，不得为了同时摆下多段规则而缩成双列小字；允许纵向滚动，标题和关闭按钮保持可见。本人操作期间也可主动打开规则，窗口明确说明牌局计时仍会继续，并显示与设置面板一致的剩余时间或“练习不限时”；关闭后按当前决定恢复焦点，不能清除已经选中的牌或动作。

## 6. 牌桌信息布局

- 庄家只在唯一庄家座位的名字旁显示醒目“庄”角标和清晰的定庄牌，不重复显示庄家姓名或抽牌者姓名。本人坐庄时，姓名、“你”标识和“庄＋定庄牌”都必须保留，空间不足可分行，但在 568×320 和自动旋转画布中不得互相挤压或被左下角信息卡裁切。
- 三位其他玩家的名字旁始终显示准确的剩余手牌数，并随摸牌、组牌和弃牌更新；小屏不能隐藏。568×320 与自动旋转画布中的余牌数字和“电脑”身份标识不得小于 13px，并保持高对比粗体。
- 可见座位摘要不重复本人手牌数，也不显示“牌组 0 组”“暗坎 0”等零值；非零牌组或暗坎才出现短标签。四个座位的读屏摘要仍完整包含姓名、余牌、公开牌组、暗坎、在线/托管和庄家/当前回合状态。
- 保留四个方向的当前回合、待响应和动作反馈，因为它们会影响玩家判断。568×320 与自动旋转画布中的“当前回合”“待响”、方向动作、庄家“庄”、本人“你”和记录数量不得小于 13px；牌堆单位“张”不得小于 10px。颜色和位置只能作为辅助，不能用 8–11px 小字承载唯一轮次含义。
- 没有待响应牌时不显示“暂无待响应牌”占位框。
- 开局定庄使用短而明确的两阶段仪式：先在牌桌中央显示红色、细长、两头圆的四色牌背和“正在翻定庄牌”，再在同一位置淡入真实牌面并显示完整牌名与“某某坐庄”，最后在对应座位静态显示庄标。揭晓前不得由座位边框或常驻牌面提前暴露结果；真实牌面应留出足够辨认时间。客户端按房间与局数建立唯一发牌展示键，新手牌不能在旧结算页提前出现，一局只能播放一轮发牌；发牌期间逐步揭示手牌，声明面板出现时立即结束残余动画并显示完整手牌。慢设备按绝对时间跳过错过的帧，不能把发牌拖到暗坎声明之后。减少动态偏好下改为无翻转、无飞行的静态结果。

中央组合固定在牌桌视觉中心：

- 牌堆在左，待响应牌在右，两者整体居中。
- 牌堆位置固定，不因待响应牌出现或消失而移动。
- 牌堆用八张重叠的传统四色牌牌背绘制：细长、上下两头圆、红色背面，不使用普通扑克牌的宽矩形或蓝色花纹。
- 顶层牌背居中显示准确余量，并提供可访问文本。
- 本人或其他玩家尚无公开牌组时，不画带边框的空牌组卡片，也不显示“暂无牌组”；内容出现后再显示牌组。实现可以保留不可见的布局与飞牌动画锚点，但不得因此挤动中央牌堆。
- 流水为空时不画空卡片或“暂无流水”；出现流水后用不小于 13px 的“出牌者 → 接牌者”短标题配合实际牌面，完整含义通过无障碍标签保留，避免小屏为了长句而缩小字号。四条方向流水始终由按 `seatIndex` 排序的固定座位环计算，并保留稳定容器和牌节点；普通同步不能卸载重建或互换归属，切换顺/逆时针只镜像显示位置。被吃、碰、开、胡时只移动实际目标牌，其他流水牌保持原位。
- 568×320 等低高度画布中，上方玩家、左右玩家、中央区和本人明示牌区必须全部收纳在牌桌边界内；内容较多时只允许各自牌区内部滚动，不能把整行伸出牌桌后裁掉，也不能通过缩小牌字换空间。320×568 竖持自动旋转后须使用相同的有效高度分配，牌桌与底部手牌操作行的逻辑高度应和横持一致。

### 最近操作

- 玩家可从顶部“记录”打开本局最近 16 步，最新操作排在最前；默认收起，不长期占用牌桌空间。
- 记录使用玩家昵称和“（你）/（机器人）”身份说明，动作写成“打出一张牌”“吃牌”“超时，系统自动过”等完整中文，不暴露 `seat_1`、`DISCARD` 等内部标识。
- 记录覆盖出牌、吃、碰、开、胡、抓、过、超时处理、定庄和断线托管；将牌或金条的单张明示也统一写作“吃”，自动摸牌等高频过程信息不写入，避免噪声淹没关键步骤。
- 面板可滚动并具有模态名称、焦点约束和 Escape 关闭；关闭后焦点回到“记录”按钮，并明确提醒查看期间牌局计时仍会继续。新的本人操作窗口到来时自动收起，不能遮挡决策。点击牌桌遮罩只关闭记录，不得穿透并选择手牌或触发动作。
- 历史只用于解释已经发生的步骤，不参与规则裁决；下一局开始时清空，重连后至少保留服务端当前最后一步。

## 7. 手牌与出牌

- 小屏手牌保持单行横向滚动，不强求一次显示全部。
- 手牌存在横向溢出时，必须同时显示带方向的“‹ 前翻 / 后翻 ›”文字按钮，并在两者之间显示“1–9 / 18”形式的实际可见牌号范围；小屏按钮触控区至少 44×36px、文字不小于 13px，不能只放难以理解和点击的细小箭头。按钮只移动视口，不得选择或打出任何牌，手指横滑仍然可用。
- 在 667×375 有效画布下，自适应手牌实际牌面宽约 40–44px、间距约 2px、主要字形不小于约 22px；首屏目标约 9–10 张。
- 在 568×320 的老旧小屏下仍保留至少 40×52px 的牌面和 22px 以上主字，首屏至少完整显示 8 张；本人手牌计数和实时可见牌号范围不得小于 13px。优先压缩本人信息栏、操作坞外框和无效间距，不再缩小牌字。
- 实际牌面填满点击槽，避免槽位看似很大但牌字很小。
- 发牌动画逐张展示期间，以及公开手牌数与本人私有手牌数量尚未一致期间，不开放声明确认、选牌或动作按钮。声明面板显示“正在同步完整手牌”，操作坞分别显示“正在整理手牌”或“正在同步手牌”；待画面稳定、权威手牌到齐并重新计算声明建议后再允许操作，避免玩家点牌时牌面突然移动。
- 声明阶段断网时继续保留已选亮鱼和暗坎，不关闭声明面板，也不假装已经提交；所有选项与确认按钮暂时锁定，主按钮明确显示“等待网络恢复”。恢复后保持原选择并重新开放提交；发送失败或 3.5 秒没有获得权威状态确认时解除“提交中”，把焦点还给确认按钮并提示重新提交。
- 等待他人、选择吃碰候选或断网恢复时，自己的全部手牌仍保持完整对比度，方便提前整理思路；不能因为按钮暂不可点就把整手牌统一变灰。
- 牌面使用高对比粗体；四色牌中最低对比的红底黑字也须达到普通正文 4.5:1 基线，键盘焦点有独立轮廓。所有正面牌除底色外还显示“黄 / 红 / 绿 / 白 / 金”文字印：大字牌位于左上，长牌位于上下主字之间，不能遮挡主字或与右上的选择、规则保护标记冲突。
- 单击牌面只改变选中项；重复点击或双击都不会直接出牌。确认提交后保持“正在打出”状态直到服务端手牌更新或合理的失败恢复窗口结束，不能因普通网络延迟过早恢复按钮；本人预演的出牌飞行动画在服务端确认到达后不得再播放一次。
- 手牌在对局中可随时预选一张普通牌；轮到本人弃牌时，右侧统一操作坞用固定位置的单字主按钮“出”提交。按钮不重复完整牌名，选中状态由真实手牌的抬起、描边、勾选和读屏标签共同表达；不会因为进入回合自动打出。
- 吃、碰、开、胡、过和确认出牌提交后，操作坞必须立即显示“正在确认”并锁住同一决策，服务端随后明确回执“已收到”或可读的失败原因。成功回执可短暂收起文字，但在决策真正变化前仍不得重复提交；拒绝或 2.5 秒未收到确认时解除锁定并提示重试，出牌失败保留原选择。回执只表示请求到达，最终牌面仍以服务端状态为准。
- 需要本人决定时，操作坞保持单行固定高度，只显示紧凑倒计时、单字主动作和当前合法快捷动作；最后 5 秒切换为高对比警示，不再堆叠操作标题与说明。
- 非本人回合保持操作坞位置稳定但视觉内容为空；当前操作者由中央方向箭头、座位高亮和待响标记表达，不再重复显示“某某正在操作 / 轮到你时会提醒”。断线或同步异常仍优先显示紧凑的“操作已暂停”。
- 选中的手牌除抬起和描边外还显示勾选标记，并通过读屏名称说明“已选中”；不能只依赖蓝色光效表达选择状态。
- 紧急提示的动效遵循系统 `prefers-reduced-motion`，关闭动效后仍须靠边框、底色和文字表达紧急程度。
- 将牌和金条不可作为弃牌选中；仅在本人实际弃牌阶段降低少量饱和度并显示“留”标记，读屏说明“规则保护，不能打出”。阶段、手牌和服务端响应变化时，应正确清理或恢复选择。
- “出”和“吃”共用操作坞的主动作位置并根据阶段动态改名；胡、开、碰、过/抓只作为当前合法的单字快捷动作出现。胡、开、碰点击后由服务端从合法方案中自动执行，不打开二级选择。
- 吃牌直接操作真实手牌：可加入合法吃法的牌保持可点，已选牌使用独立高亮；所选牌 ID 恰好对应一种合法组合时“吃”启用，中央待响牌自动计入。三卒可以先确认，也可继续加入第三张卒切换为四色卒；单张吃无需选择手牌。Escape 只清空当前多张吃牌草稿，不提交动作。

## 8. 小屏验收基线

必须覆盖以下画布，不按设备型号或 UA 分叉：

- 有效横屏：568×320、667×375、740×360、812×375、844×390、852×393、896×414、915×412、926×428。
- 物理竖持自动旋转：320×568、375×667、390×844、393×852、412×915、428×926；旋转后必须复用对应有效横屏的尺寸分配。
- 平板与桌面基线：1024×768、1280×720。
- 568×320 老旧横屏必须保证牌字、八张首屏手牌和全部操作按钮可达，三区之间不得交叠；所有代表视口均不得出现页面级横向或纵向溢出。
- 同一局在物理横持与竖持自动旋转之间切换时，牌桌与底部操作行的逻辑高度不能改变或裁切本人明示牌区。

关键截图场景包括定庄完成、普通等待、待响应牌出现、选牌待确认、设置展开、两种座位方向、声明和结算。详细步骤见 [TESTING.md](TESTING.md)。

## 9. 结算页

- 牌局先进入结束状态、权威明细尚未到齐时，明确显示“正在整理本局得分”，并禁用“下一局”和“全桌返回大厅”，不能让房主跳过迟到的结果。
- 好友桌存在其他真人时，“下一局”是影响全桌且会关闭当前结算的操作，必须二次确认；确认层在 568×320 和自动旋转画布内完整可达并约束焦点。纯机器人桌和单人练习不增加这一步。
- 明细到齐后首先用大号摘要说明谁胡牌或是否流局，并突出“你本局 ±N 分”；删除面向开发者的内部动作码。
- 各家摘要始终把本人排在第一位，并用“（你）”“赢家”文字标识，不只依赖边框颜色；非本人赢家紧随其后。每行直接显示总分和牌数，点击整行才展开牌组、手牌与计分依据。
- 667×375、568×320 等紧凑触屏默认折叠四家长明细，以单列大字摘要优先回答“谁赢、我多少分”；牌面明细按需展开，不为同时塞下全部内容而缩小牌字。桌面默认展开，方便一次核对完整牌局。
- 紧凑触屏展开某家的长明细后，该玩家姓名、身份和总分摘要在其明细范围内保持可见；滚动到手牌或分数时不能只剩牌面而失去“正在看谁”的上下文。
- 结算标题和本人输赢固定在顶部，玩家明细使用唯一的中间滚动区，房主整桌操作固定在底部且不得覆盖内容。紧凑有效画布的固定头使用横向紧凑布局，只长期显示结算标题、胜负、本局分和累计模式所需的局数/累计分；辅助说明保留给读屏但不占用垂直空间，累计信息最多自然换成两行且不缩小核心字号。设置和个人退出继续留在独立顶栏，结算内容不得覆盖顶栏。
- 有效高度不超过 500px 时固定结算头不超过 64px，中间明细区至少占面板高度 40%；320–428px 有效高度的折叠首屏至少完整显示前三位玩家摘要，底部操作始终完整可见。展开牌型后牌宽不小于 32px、主字不小于 16px，当前玩家摘要继续吸顶。
- “全桌返回大厅”会影响所有玩家，房主点击后必须二次确认；确认层默认聚焦“继续看结算”，支持 Escape 取消并把焦点还给原按钮，防止小屏滚动时误触带走整桌。
- “下一局”和“全桌返回大厅”确认发送后必须互斥锁定，分别显示“正在开始下一局…”或“正在返回房间大厅…”，并说明整桌请求已发送。连续点击只发送一次；8 秒没有权威阶段变化时恢复两项操作并提示重试，连接失败时不能伪装成已经生效。等待期间结算明细和个人退出仍可使用。
- 单人练习结算把“再练一局”和“返回玩法选择”作为两项个人操作；返回后必须看到完整三种玩法入口。好友房仍保留房主的整桌下一局和返回准备页语义，快速桌仍使用个人重新配桌，三种模式不得共用一个含义模糊的“大厅”。


### 中央待响与收牌动画

- 抓牌在 200ms 内按牌背飞入中央，随后停稳并翻面；揭晓完成才开放响应和启动计时。低性能设备以约 30 帧/秒更新并按绝对时间跳帧。
- 普通移牌约 350ms。A 的弃牌先到中央；轮询无人取得才落到 A→B 流水，B 吃时从流水移动到牌组。
- B 自摸普通牌只轮询一次，并允许 B 同轮选择吃；无人取得且 B 不吃时自动落 B→C，只开放 C 的吃／抓。将和金条不得落流水。
- 同一牌 ID 在飞行、中央、流水和牌组之间只呈现一次。吃、碰、开移动真实组合牌面，且只能飞向已渲染牌面的精确矩形；目标不存在时直接显示权威结果，绝不退化为飞向容器中央。飞牌提前到达并短暂停稳，胡牌收牌完成后再显示结算。
- 重连按绝对时间恢复正在发生的展示；过期事件不重播。减少动态效果下静态切换，不翻转和飞行。
