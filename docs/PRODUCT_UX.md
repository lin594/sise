# 产品与体验规范

## 1. 当前产品范围

当前正式支持：

- 单人练习：每次进入都创建独立房间，只允许一名真人，空座由机器人补足；陌生访客不能通过旧链接串入。
- 好友同桌：创建私有房、复制邀请链接、自由选座，房主可以添加和调节机器人。
- 声明、完整牌局、胡牌/流局结算、下一局、整桌返回大厅和个人退出。

尚未作为可用功能交付：账号注册登录、公开房间大厅、自动匹配、排行榜和 Redis 状态持久化。正式玩家入口不展示这些尚不能完成的操作；规划信息只留在文档中，不能让玩家走进死路。

首次进入保留两个单一任务页面：先确认系统预填且可编辑的临时昵称，再选择“单人练习”或“好友同桌”。昵称页的主按钮明确写“下一步：选择玩法”，规则只在全局顶栏出现一次；568×320 下输入字不小于 18px、标签不小于 15px、两个操作按钮文字不小于 16px。玩法页持续显示当前昵称和“修改昵称”，返回修改时保留名字并把焦点放回输入框；两张可用模式卡必须同时完整可见，单人练习标为新手推荐，选择状态同时使用文字、边框和 `aria-pressed`。好友邀请链接仍直接显示“加入好友房”，不经过普通玩法选择。

好友邀请链接打开后，昵称页必须直接说明这是好友房邀请、下一步需要选择空座位，主按钮使用“加入好友房”，不能再显示只适用于单人练习的介绍。好友房内根据状态给出单一下一步：未入座时提示选空座，普通玩家入座后提示等待房主，房主提示分享链接并在四席就绪后开始。极小屏压缩邀请说明，优先让空座位进入首屏。复制邀请成功属于正向状态，使用短暂的绿色提示，不得伪装成红色错误；普通 HTTP 局域网试玩没有现代 Clipboard API 时也必须提供兼容复制。若浏览器连兼容复制也拒绝，显示站内大字链接弹层并自动全选，支持长按复制、焦点约束和安全关闭，不调用不可控的系统 `prompt`，也不要求玩家理解安全上下文限制。

好友房等待页采用固定标题、独立滚动内容和固定下一步三段式布局；底部操作必须参与布局且使用不透明背景，不能覆盖座位。等待阶段始终提供完整文字“离开房间”，二次确认默认聚焦“继续等待”，Escape、遮罩和取消都回到原按钮。确认后清除房间凭证并返回模式大厅；房主还要明确知道房主会转交或空房会关闭。568×320 首屏至少完整呈现房间控制、邀请、固定下一步和 80px 高的首排座位内容。

房主配置机器人时使用“轻松 / 标准 / 高手”三个清楚的大按钮，不要求拖动精细滑杆。默认“标准”；三档分别对应服务端强度 20、50、85。旧客户端和服务端仍保留 0–100 数值兼容，界面按 `<35`、`35–69`、`≥70` 映射回三档显示。

好友房房主缺人时，固定操作区显示“补齐 N 位电脑”，一次用标准难度机器人填满全部空座；已有真人、已有机器人和座位位置不得变化，补齐后也不得自动开局。等待房标题直接说明“还差 N 位即可开局”“四席已就绪”“请先选择座位”或“等待牌友重新上线”，避免只显示无行动含义的“房间准备中”。逐席添加、移除和调节难度仍然保留。

## 2. 核心体验原则

主要受众包含老年玩家，因此产品优先保证：

- 牌字清楚、主要动作稳定可点，不能为了在一屏塞下全部手牌而无限缩小。
- 小尺寸手机也能完成全部流程，不依赖双击、精细拖拽或隐藏手势。
- 不禁止浏览器和系统的页面缩放；低视力玩家始终可以使用双指放大，按钮自身仍使用稳定的单击语义防止误触。
- 牌桌只保留影响当前决策的信息；同一信息不在顶部、中央和座位处重复出现。
- 设置和退出始终可见，但与牌局内容有明确边界。
- 所有关键状态既有视觉反馈，也有易懂文字，不能只靠颜色区分。
- 每张牌的读屏名称必须包含颜色和传统牌面字；金条还要明确读作“金条公/侯/伯/子/男”，待响应牌不能只靠星号表达。
- 网络短暂中断不能清空牌桌或手牌，玩家应能明确知道系统仍在自动恢复。
- 单人练习中的在线真人声明、响应和出牌不限时，并明确显示“练习不限时”；机器人和断线后的托管仍按计时推进，避免无人牌局停滞。
- 好友房默认给真人 30 秒完成响应或出牌、45 秒完成开局声明；倒计时用于建立预期而非催促。每名真人在自己的每个决策窗口都可主动增加一次 20 秒，按钮紧邻倒计时且使用完整中文；旧窗口的迟到请求不得延长下一次决策。
- 开局声明由系统预选推荐方案，主按钮使用“无需声明，开始游戏”或“开始游戏 · 亮鱼 N 组 · 暗坎 N 个”，不能只写含义模糊的“确认”。极小屏常驻“上下滑调整 · 手牌可前后翻”提示；手牌到齐后焦点落到开始按钮，手牌同步中或提交完成后聚焦声明弹层，Tab 始终留在弹层内。
- 新的真人操作窗口开始时，只发出一次温和提醒；默认响铃加震动，可改为仅响铃或完全关闭。浏览器不支持或尚未允许音频时静默降级，视觉提示始终保留。

触控尺寸根据有效画布自适应，不设全局固定 48px 的硬指标；验收标准是手指能稳定点击、控件互不遮挡且全部可达。

## 3. 顶部控制区

声明、对局和结算阶段均保留独立顶栏：

- 左侧展示简洁“四色牌”招牌。
- 右侧展示带文字的“记录”“设置”和“退出”；“记录”用于回看本局最近操作，不承载规则状态或开发信息。老旧小屏上的按钮文字不得小于 13px。
- 顶栏适配安全区，只承载全局控制和连接状态，不显示庄家、回合、牌堆或待响应等牌局信息。
- 牌桌和弹层从顶栏下方开始，不得与顶栏相交。
- 设置和记录面板从顶栏下方展开，尺寸使用旋转后的有效画布而不是物理屏幕的原始宽高；小屏内容过多时只在面板内部滚动。主要选项文字不小于 14px，辅助说明不小于 13px，最底部入口必须能够滚动到并操作。

退出是个人退出：确认后停止自动重连、清除当前房间凭证、离开连接并返回模式大厅。确认弹层默认聚焦“继续游戏”，焦点不得逃到背景，Escape 或点击遮罩只能取消并把焦点还给退出按钮，避免误按回车离桌。所有应用自有的全屏弹层必须使用有效游戏画布的坐标系；手机竖持且牌桌自动旋转时，遮罩、文字和按钮随牌桌一起旋转并完整留在物理屏幕内。结算页的“下一局”和“整桌返回大厅”必须标注为房主操作，避免混淆。

## 4. 网络状态与恢复

- 大厅显示简洁“网络正常”，不向普通玩家暴露座位 ID、房主内部 ID 或 token。
- 牌局连接正常时不额外占用桌面空间；断线、重试和刚恢复时，在顶部控制栏显示高对比文字状态。
- 离线时提示“联网后自动恢复”；网络或服务短暂异常时说明系统仍会继续，并提供“立即重试”。
- 断线期间保留最后看到的牌桌与手牌，但禁用所有牌局动作；恢复后以服务端权威状态覆盖本地画面。
- 断线、自动重试和重连期间，右侧操作坞必须用明确的“操作已暂停”恢复状态替换灰色动作按钮，说明无需反复点击；极小屏仍要完整显示“自动恢复”含义，不能只依赖顶部状态点。
- 刷新页面或手机系统回收页面后，只要本机房间凭证仍有效，就直接回到原座，不要求重新输入昵称或再次选择模式。
- 自动恢复尚未成功时显示独立恢复页，并始终提供“放弃恢复，返回首页”。恢复成功后，顶部至少保留 6 秒“已恢复 · 请核对手牌”，并在空间允许时说明离线期间系统可能代为操作；提示不得遮挡或抢走当前操作。若房间已经结束/回收、原座失效、玩家被移出或同一座位已在其他窗口恢复，应立即停止自动重试，清楚说明原因并只保留“返回首页”；不能把玩家困在无意义的恢复循环中。
- 同一座位被新窗口接管后，旧窗口保留最后画面供辨认，但所有动作冻结并显示“已停止自动恢复”；新窗口必须持续保持真人控制，两个页面不能来回抢占。
- 创建房间等 HTTP 操作被限流时，应显示服务端给出的安全中文原因和准确等待秒数；服务异常只显示可操作的通用提示，不能把内部路径或异常详情暴露给玩家。
- 轻量身份以昵称和房间凭证为主，不要求老年玩家先注册账号或记忆密码。账号体系未交付前，不得把房间 token 描述成正式登录。
- 真人首次入座后昵称在本房间内保持稳定；同名真人自动显示“昵称（2）”等清晰后缀，避免流水、座位和结算无法辨认。类似“机器人2”的旧式机器人昵称由真人使用时仍需标明“（玩家）”。
- 预先配置的机器人从友好昵称池中随机取名，同一牌桌内不得重名或与真人重名；昵称本身不要求带“机器人”字样。牌桌座位、操作提示和结算必须另行显示清晰的“电脑”或“机器人”身份标识，小屏也不得隐藏该标识。
- 真人断线后先保留默认 5 秒重连宽限，显示“真人离线”且不允许机器人代操作；到期后标准屏显示“暂由机器人”，极小屏显示醒目的“托管中”。全程保留真人昵称，不得改名为带 `[BOT]` 的名字，也不得套用预先配置机器人的随机昵称。
- 真人重新连接后恢复“真人在线”状态，并明确提示托管期间的最新牌局已经同步。

## 5. 牌面显示设置

玩家可以分别设置“我的牌”和“桌面牌”：

| 模式 | 表现 |
|---|---|
| 大字 | 单个正向大字，优先可读性 |
| 自适应 | 小屏使用大字，标准桌面使用长牌 |
| 长牌 | 传统上下双字的细长牌面 |

两类设置默认均为“自适应”，并保存在浏览器本地：

- “我的牌”覆盖声明预览、实时手牌、候选中的本人手牌和本人结算手牌。
- “桌面牌”覆盖待响应牌、定庄牌、所有玩家公开牌组、流水、亮鱼、动画和结算中的其他牌。
- 旧版 `simple/full` 偏好迁移为桌面牌“大字/长牌”，我的牌保持自适应。

设置还提供顺时针与逆时针座位方向。切换只镜像左右玩家及其牌组、流水、动作反馈、回合指向和飞牌动画；自己和对家不动，服务器座位号与实际出牌顺序不变。默认保持逆时针显示。操作提醒与这些显示偏好一并保存在本机；轮到本人时页面标题同步改为“轮到你了”，便于从浏览器标签或任务切换界面识别，操作窗口结束后恢复。

声明预览与实时手牌都必须优先保证“我的牌”可辨认。568×320 等老旧小屏中的大字/自适应声明牌面不小于 40×44px、主字不小于 22px；长牌不小于 28×52px、主字不小于 16px。声明手牌保持单行横滑，发生溢出时同时提供至少 44×34px 的“前翻 / 后翻”文字按钮，不能要求玩家自行发现隐藏手势；翻看不会改变亮鱼、暗坎或提交状态。

“牌局中屏幕常亮”默认开启，只在已连接的声明和正式对局阶段申请屏幕常亮；切到后台、进入结算、退出房间或关闭设置时立即释放。该能力属于渐进增强，浏览器或非安全来源不支持时不得影响游戏。

设置面板必须使用不透底的高对比背景，避免牌桌文字穿透干扰阅读；关闭按钮在极小屏仍需保留稳定触控面积。打开后焦点进入面板，Tab 不得逃到背景；Escape、关闭按钮或点击面板外均可关闭，并把焦点还给设置按钮。声明阶段允许调整牌面，便于先看清手牌再确认。正式对局中一旦轮到本人响应或出牌，已展开的设置会自动关闭，设置入口保持原位和“设置”名称并以中性样式禁用，完整原因通过无障碍名称和鼠标提示说明；行动引导只由右侧操作坞承担，避免顶部出现第二个误导性的主按钮。

规则速查使用可通过 Escape 关闭、焦点不会逃到背景的模态窗口。无论玩家正在看设置还是规则，一旦新的本人操作窗口开始，遮挡层必须立即关闭，并把键盘焦点移到第一张可选手牌或第一个合法动作；视觉提醒、响铃和震动仍按原设置执行。

## 6. 牌桌信息布局

- 庄家只在唯一庄家座位的名字旁显示醒目“庄”角标和缩小后的定庄牌，不重复显示庄家姓名或抽牌者姓名。
- 三位其他玩家的名字旁始终显示准确的剩余手牌数，并随摸牌、组牌和弃牌更新；小屏不能隐藏。
- 可见座位摘要不重复本人手牌数，也不显示“牌组 0 组”“暗坎 0”等零值；非零牌组或暗坎才出现短标签。四个座位的读屏摘要仍完整包含姓名、余牌、公开牌组、暗坎、在线/托管和庄家/当前回合状态。
- 保留四个方向的当前回合、待响应和动作反馈，因为它们会影响玩家判断。
- 没有待响应牌时不显示“暂无待响应牌”占位框。

中央组合固定在牌桌视觉中心：

- 牌堆在左，待响应牌在右，两者整体居中。
- 牌堆位置固定，不因待响应牌出现或消失而移动。
- 牌堆用八张重叠的传统四色牌牌背绘制：细长、上下两头圆、红色背面，不使用普通扑克牌的宽矩形或蓝色花纹。
- 顶层牌背居中显示准确余量，并提供可访问文本。
- 本人或其他玩家尚无公开牌组时，不画带边框的空牌组卡片，也不显示“暂无牌组”；内容出现后再显示牌组。实现可以保留不可见的布局与飞牌动画锚点，但不得因此挤动中央牌堆。
- 流水为空时不画空卡片或“暂无流水”；出现流水后用较大的“出牌者 → 接牌者”短标题配合实际牌面，完整含义通过无障碍标签保留，避免小屏为了长句而缩小字号。
- 568×320 等低高度画布中，上方玩家、左右玩家、中央区和本人明示牌区必须全部收纳在牌桌边界内；内容较多时只允许各自牌区内部滚动，不能把整行伸出牌桌后裁掉，也不能通过缩小牌字换空间。320×568 竖持自动旋转后须使用相同的有效高度分配，牌桌与底部手牌操作行的逻辑高度应和横持一致。

### 最近操作

- 玩家可从顶部“记录”打开本局最近 16 步，最新操作排在最前；默认收起，不长期占用牌桌空间。
- 记录使用玩家昵称和“（你）/（机器人）”身份说明，动作写成“打出一张牌”“吃牌”“超时，系统自动过”等完整中文，不暴露 `seat_1`、`DISCARD` 等内部标识。
- 记录覆盖出牌、吃、碰、开、胡、抓、过、超时处理、定庄和断线托管；将牌或金条的单张明示也统一写作“吃”，自动摸牌等高频过程信息不写入，避免噪声淹没关键步骤。
- 面板可滚动并具有模态名称、焦点约束和 Escape 关闭；关闭后焦点回到“记录”按钮，并明确提醒查看期间牌局计时仍会继续。新的本人操作窗口到来时自动收起，不能遮挡决策。点击牌桌遮罩只关闭记录，不得穿透并选择手牌或触发动作。
- 历史只用于解释已经发生的步骤，不参与规则裁决；下一局开始时清空，重连后至少保留服务端当前最后一步。

## 7. 手牌与出牌

- 小屏手牌保持单行横向滚动，不强求一次显示全部。
- 手牌存在横向溢出时，必须同时显示带方向的“‹ 前翻 / 后翻 ›”文字按钮，并用边缘提示表明还有未显示的牌；小屏按钮触控区至少 44×34px，不能只放难以理解和点击的细小箭头。按钮只移动视口，不得选择或打出任何牌，手指横滑仍然可用。
- 在 667×375 有效画布下，自适应手牌实际牌面宽约 40–44px、间距约 2px、主要字形不小于约 22px；首屏目标约 9–10 张。
- 在 568×320 的老旧小屏下仍保留至少 40×52px 的牌面和 22px 以上主字，首屏至少完整显示 8 张；优先压缩本人信息栏、操作坞外框和无效间距，不再缩小牌字。
- 实际牌面填满点击槽，避免槽位看似很大但牌字很小。
- 发牌动画逐张展示期间，以及公开手牌数与本人私有手牌数量尚未一致期间，不开放声明确认、选牌或动作按钮。声明面板显示“正在同步完整手牌”，操作坞分别显示“正在整理手牌”或“正在同步手牌”；待画面稳定、权威手牌到齐并重新计算声明建议后再允许操作，避免玩家点牌时牌面突然移动。
- 等待他人、选择吃碰候选或断网恢复时，自己的全部手牌仍保持完整对比度，方便提前整理思路；不能因为按钮暂不可点就把整手牌统一变灰。
- 牌面使用高对比粗体；四色牌中最低对比的红底黑字也须达到普通正文 4.5:1 基线，键盘焦点有独立轮廓。
- 单击牌面只改变选中项；重复点击或双击都不会直接出牌。
- 出牌确认使用牌桌右侧统一操作坞：未选牌显示禁用的“先选牌”，选中合法牌后显示高亮“出牌”。
- 需要本人决定时，操作坞先用醒目的“该你操作了”及准确剩余秒数建立优先级，再用短句说明当前该选牌还是选动作；667×375 下说明文字不得小于 12px，可换行但不能裁切。最后 5 秒切换为高对比警示。
- 非本人回合保持操作坞位置稳定，但不显示灰色的胡、开、碰、吃、过等假操作按钮；只显示“某某正在操作 / 轮到你时会提醒”的非按钮等待卡。这样既不推动牌桌布局，也不会让玩家误以为自己漏了操作。断线或同步异常仍优先显示“操作已暂停”。
- 选中的手牌除抬起和描边外还显示勾选标记，并通过读屏名称说明“已选中”；不能只依赖蓝色光效表达选择状态。
- 紧急提示的动效遵循系统 `prefers-reduced-motion`，关闭动效后仍须靠边框、底色和文字表达紧急程度。
- 将牌和金条不可作为弃牌选中；仅在本人实际弃牌阶段降低少量饱和度并显示“留”标记，读屏说明“规则保护，不能打出”。阶段、手牌和服务端响应变化时，应正确清理或恢复选择。
- 吃、碰、开、胡、过与出牌共用操作坞的空间，但保持各自候选与确认流程。
- 吃、碰、开存在多种组合时，候选层使用明确的模态语义并自动聚焦第一种组合；Tab 不得落回被遮住的牌桌。Escape、取消按钮或点击遮罩只取消本次选择并把焦点还给原动作按钮，不能误提交或消耗操作机会。

## 8. 小屏验收基线

必须覆盖以下有效画布：

- 375×667 竖屏设备自动使用旋转后的横向画布。
- 320×568 老旧竖屏设备自动使用 568×320 横向画布。
- 568×320 老旧横屏设备必须保证牌字、八张首屏手牌和全部操作按钮可达，三区之间不得交叠。
- 568×320 与 320×568 自动旋转后的同一有效画布必须采用相同的牌桌和底部操作行高度，不能因物理方向改变而裁切本人明示牌区。
- 667×375（iPhone SE 级别）优先保证字号、触控和信息不重叠。
- 1280×720 桌面验证正常的长牌与空间利用。

关键截图场景包括定庄完成、普通等待、待响应牌出现、选牌待确认、设置展开、两种座位方向、声明和结算。详细步骤见 [TESTING.md](TESTING.md)。

## 9. 结算页

- 牌局先进入结束状态、权威明细尚未到齐时，明确显示“正在整理本局得分”，并禁用“下一局”和“全桌返回大厅”，不能让房主跳过迟到的结果。
- 明细到齐后首先用大号摘要说明谁胡牌或是否流局，并突出“你本局 ±N 分”；删除面向开发者的内部动作码。
- 各家摘要始终把本人排在第一位，并用“（你）”“赢家”文字标识，不只依赖边框颜色；非本人赢家紧随其后。每行直接显示总分和牌数，点击整行才展开牌组、手牌与计分依据。
- 667×375、568×320 等紧凑触屏默认折叠四家长明细，以单列大字摘要优先回答“谁赢、我多少分”；牌面明细按需展开，不为同时塞下全部内容而缩小牌字。桌面默认展开，方便一次核对完整牌局。
- 结算标题和本人输赢固定在顶部，玩家明细使用唯一的中间滚动区，房主整桌操作固定在底部且不得覆盖内容。设置和个人退出继续留在独立顶栏，结算内容不得覆盖顶栏。
- “全桌返回大厅”会影响所有玩家，房主点击后必须二次确认；确认层默认聚焦“继续看结算”，支持 Escape 取消并把焦点还给原按钮，防止小屏滚动时误触带走整桌。
