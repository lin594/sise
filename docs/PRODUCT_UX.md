# 产品与体验规范

## 1. 当前产品范围

当前正式支持：

- 单人练习：一名真人开局，空座由机器人补足。
- 好友同桌：创建私有房、复制邀请链接、自由选座，房主可以添加和调节机器人。
- 声明、完整牌局、胡牌/流局结算、下一局、整桌返回大厅和个人退出。

尚未作为可用功能交付：账号注册登录、公开房间大厅、自动匹配、排行榜和 Redis 状态持久化。界面若保留相关入口，必须明确标注“即将开放”，不能让玩家误认为已经可用。

好友邀请链接打开后，昵称页必须直接说明这是好友房邀请、下一步需要选择空座位，主按钮使用“加入好友房”，不能再显示只适用于单人练习的介绍。好友房内根据状态给出单一下一步：未入座时提示选空座，普通玩家入座后提示等待房主，房主提示分享链接并在四席就绪后开始。极小屏压缩邀请说明，优先让空座位进入首屏。复制邀请成功属于正向状态，使用短暂的绿色提示，不得伪装成红色错误。

## 2. 核心体验原则

主要受众包含老年玩家，因此产品优先保证：

- 牌字清楚、主要动作稳定可点，不能为了在一屏塞下全部手牌而无限缩小。
- 小尺寸手机也能完成全部流程，不依赖双击、精细拖拽或隐藏手势。
- 牌桌只保留影响当前决策的信息；同一信息不在顶部、中央和座位处重复出现。
- 设置和退出始终可见，但与牌局内容有明确边界。
- 所有关键状态既有视觉反馈，也有易懂文字，不能只靠颜色区分。
- 每张牌的读屏名称必须包含颜色和传统牌面字；金条还要明确读作“金条公/侯/伯/子/男”，待响应牌不能只靠星号表达。
- 网络短暂中断不能清空牌桌或手牌，玩家应能明确知道系统仍在自动恢复。
- 默认给真人 30 秒完成响应或出牌、45 秒完成开局声明；倒计时用于建立预期而非催促。机器人仍按独立的短思考时间行动，避免拖慢单人练习。
- 新的真人操作窗口开始时，只发出一次温和提醒；默认响铃加震动，可改为仅响铃或完全关闭。浏览器不支持或尚未允许音频时静默降级，视觉提示始终保留。

触控尺寸根据有效画布自适应，不设全局固定 48px 的硬指标；验收标准是手指能稳定点击、控件互不遮挡且全部可达。

## 3. 顶部控制区

声明、对局和结算阶段均保留独立顶栏：

- 左侧展示简洁“四色牌”招牌。
- 右侧展示带文字的“设置”和“退出”。
- 顶栏适配安全区，只承载全局控制和连接状态，不显示庄家、回合、牌堆或待响应等牌局信息。
- 牌桌和弹层从顶栏下方开始，不得与顶栏相交。
- 设置面板从顶栏下方展开；小屏内容过多时面板内部滚动。

退出是个人退出：确认后停止自动重连、清除当前房间凭证、离开连接并返回模式大厅。结算页的“下一局”和“整桌返回大厅”必须标注为房主操作，避免混淆。

## 4. 网络状态与恢复

- 大厅显示简洁“网络正常”，不向普通玩家暴露座位 ID、房主内部 ID 或 token。
- 牌局连接正常时不额外占用桌面空间；断线、重试和刚恢复时，在顶部控制栏显示高对比文字状态。
- 离线时提示“联网后自动恢复”；重试失败时说明系统仍会继续，并提供“立即重试”。
- 断线期间保留最后看到的牌桌与手牌，但禁用所有牌局动作；恢复后以服务端权威状态覆盖本地画面。
- 刷新页面或手机系统回收页面后，只要本机房间凭证仍有效，就直接回到原座，不要求重新输入昵称或再次选择模式。
- 自动恢复尚未成功时显示独立恢复页，并始终提供“放弃恢复，返回首页”；该操作会清除失效房间凭证，不能把玩家困在无限重试中。
- 创建房间等 HTTP 操作被限流时，应显示服务端给出的安全中文原因和准确等待秒数；服务异常只显示可操作的通用提示，不能把内部路径或异常详情暴露给玩家。
- 轻量身份以昵称和房间凭证为主，不要求老年玩家先注册账号或记忆密码。账号体系未交付前，不得把房间 token 描述成正式登录。
- 真人首次入座后昵称在本房间内保持稳定；同名真人自动显示“昵称（2）”等清晰后缀，避免流水、座位和结算无法辨认。类似“机器人2”的真人昵称需标明“（玩家）”，为固定机器人名称让路。
- 预先配置的机器人统一标记为“机器人”。真人断线后保留原昵称，标准屏显示“暂由机器人”，极小屏保留醒目的“托管中”；不得把真人改名为带 `[BOT]` 的名字。
- 真人重新连接后恢复“真人在线”状态，并明确提示托管期间的最新牌局已经同步。

## 5. 牌面显示设置

玩家可以分别设置“我的牌”和“桌面牌”：

| 模式 | 表现 |
|---|---|
| 大字 | 单个正向大字，优先可读性 |
| 自适应 | 小屏使用大字，标准桌面使用长牌 |
| 长牌 | 传统上下双字的细长牌面 |

两类设置默认均为“自适应”，并保存在浏览器本地：

- “我的牌”覆盖声明预览、实时手牌、候选中的本人手牌和本人结算手牌。
- “桌面牌”覆盖待响应牌、定庄牌、所有玩家公开牌组、流水、亮鱼、动画和结算中的其他牌。
- 旧版 `simple/full` 偏好迁移为桌面牌“大字/长牌”，我的牌保持自适应。

设置还提供顺时针与逆时针座位方向。切换只镜像左右玩家及其牌组、流水、动作反馈、回合指向和飞牌动画；自己和对家不动，服务器座位号与实际出牌顺序不变。默认保持逆时针显示。操作提醒与这些显示偏好一并保存在本机；轮到本人时页面标题同步改为“轮到你了”，便于从浏览器标签或任务切换界面识别，操作窗口结束后恢复。

设置面板必须使用不透底的高对比背景，避免牌桌文字穿透干扰阅读；关闭按钮在极小屏仍需保留稳定触控面积。声明阶段允许调整牌面，便于先看清手牌再确认。正式对局中一旦轮到本人响应或出牌，已展开的设置会自动关闭，设置入口暂时显示“先操作”并禁用，防止面板遮挡动作或让玩家无意超时。

## 6. 牌桌信息布局

- 庄家只在唯一庄家座位的名字旁显示醒目“庄”角标和缩小后的定庄牌，不重复显示庄家姓名或抽牌者姓名。
- 三位其他玩家的名字旁始终显示准确的剩余手牌数，并随摸牌、组牌和弃牌更新；小屏不能隐藏。
- 保留四个方向的当前回合、待响应和动作反馈，因为它们会影响玩家判断。
- 没有待响应牌时不显示“暂无待响应牌”占位框。

中央组合固定在牌桌视觉中心：

- 牌堆在左，待响应牌在右，两者整体居中。
- 牌堆位置固定，不因待响应牌出现或消失而移动。
- 牌堆用八张重叠的传统四色牌牌背绘制：细长、上下两头圆、红色背面，不使用普通扑克牌的宽矩形或蓝色花纹。
- 顶层牌背居中显示准确余量，并提供可访问文本。
- 流水为空时不画空卡片或“暂无流水”；出现流水后用较大的“出牌者 → 接牌者”短标题配合实际牌面，完整含义通过无障碍标签保留，避免小屏为了长句而缩小字号。

## 7. 手牌与出牌

- 小屏手牌保持单行横向滚动，不强求一次显示全部。
- 在 667×375 有效画布下，自适应手牌实际牌面宽约 40–44px、间距约 2px、主要字形不小于约 22px；首屏目标约 9–10 张。
- 实际牌面填满点击槽，避免槽位看似很大但牌字很小。
- 牌面使用高对比粗体；四色牌中最低对比的红底黑字也须达到普通正文 4.5:1 基线，键盘焦点有独立轮廓。
- 单击牌面只改变选中项；重复点击或双击都不会直接出牌。
- 出牌确认使用牌桌右侧统一操作坞：未选牌显示禁用的“先选牌”，选中合法牌后显示高亮“出牌”。
- 需要本人决定时，操作坞先用醒目的“该你操作了”及准确剩余秒数建立优先级，再用短句说明当前该选牌还是选动作；667×375 下说明文字不得小于 12px，可换行但不能裁切。最后 5 秒切换为高对比警示。
- 选中的手牌除抬起和描边外还显示勾选标记，并通过读屏名称说明“已选中”；不能只依赖蓝色光效表达选择状态。
- 紧急提示的动效遵循系统 `prefers-reduced-motion`，关闭动效后仍须靠边框、底色和文字表达紧急程度。
- 将牌和金条不可作为弃牌选中。阶段、手牌和服务端响应变化时，应正确清理或恢复选择。
- 吃、碰、开、胡、过与出牌共用操作坞的空间，但保持各自候选与确认流程。

## 8. 小屏验收基线

必须覆盖以下有效画布：

- 375×667 竖屏设备自动使用旋转后的横向画布。
- 667×375（iPhone SE 级别）优先保证字号、触控和信息不重叠。
- 1280×720 桌面验证正常的长牌与空间利用。

关键截图场景包括定庄完成、普通等待、待响应牌出现、选牌待确认、设置展开、两种座位方向、声明和结算。详细步骤见 [TESTING.md](TESTING.md)。
