# 真实设备发布验收

正式 release 前复制本页末尾记录模板到 `docs/validation/`，填写实际发布提交、设备和证据。自动化通过不代表真机通过；默认状态全部为“未验证”。不记录玩家凭证、私有手牌或完整邀请链接。

## 使用顺序

1. 在目标提交执行 [自动化回归](TESTING.md)，确认该提交 CI gate 通过。
2. 在部署后的 HTTPS 环境完成下表；同一项在不同设备的结果分别记录，不能用桌面模拟器替代。
3. 使用两台设备测试好友邀请、换前后台与恢复，只有实际执行并观察到预期行为才能填“通过”。
4. 发布记录保留未验证、失败及阻塞 Issue；有失败或核心真机项未验证时，不能宣称正式发布验收全部通过。

## 弱网与服务恢复

| 编号 | 实际操作 | 通过标准 | 初始状态 |
|---|---|---|---|
| N1 | 对建房、快速配桌、开局请求分别施加延迟 | 显示对应进度；重复点击只提交一次；取消后的迟到结果不污染新页面 | 未验证 |
| N2 | 延迟 action ack，重复点击后恢复 | 同一决定只生效一次；过期决定被拒绝，不作用于下个窗口 | 未验证 |
| N3 | 请求超时、短暂断线、网络反复切换 | 牌桌保持可见；离线不可操作；成功恢复后同步私有手牌再解锁 | 未验证 |
| N4 | Redis 正常时重建服务容器 | 同房同座恢复；不丢累计分，不重播旧动作，不泄漏他人手牌 | 未验证 |
| N5 | 指标存储不可用期间完成一局 | 游戏及结算正常，统计缺失如实显示；不能因统计失败重试游戏操作 | 未验证 |

弱网可在测试环境用浏览器网络节流和自动化路由延迟复现；真实蜂窝网络、应用切换和服务重建结果单独记录。不要未经授权中断正在使用的生产牌局。

同一 release 可以附多个设备记录。截图先检查凭证、真实昵称等信息并脱敏；缺少物理 iPhone 或微信证据时写 `Not verified on physical iPhone / WeChat`。当前新增的是验收流程，没有声称完成任何真机测试。
