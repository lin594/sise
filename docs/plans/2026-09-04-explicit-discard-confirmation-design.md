# 明确出牌确认设计

## 问题

小屏手牌需要横向翻看，玩家选牌后还要把视线移到右侧操作坞。当前操作坞只显示“已选好，请点出牌”和“出牌”，没有重复说明即将打出哪张牌。选中牌如果已经滑出当前视野，或玩家短暂停顿后再确认，就容易忘记选择并误出牌。老年玩家更需要在最终提交前得到可读、可核对的明确反馈。

## 方案比较

- 再弹一次确认对话框：最强制，但每次出牌都增加一步，打断连续牌局，不采用。
- 只在提示文字中显示牌名：改动最小，但玩家通常把注意力放在主按钮，仍可能漏看。
- 提示和主按钮都显示牌名，同时保留手牌勾选：不增加操作步骤，又在视线移动前后提供两处一致反馈，采用。

## 详细设计

1. `GameBoard` 根据 `selectedDiscardCardId` 和当前私有手牌计算待打出牌的中文名称，例如“红相”“绿士”“金条侯”。只传展示文本，不改变牌 ID、动画或 `discard_card` 消息。
2. `ActionPanel` 增加可选的 `selectedDiscardCardLabel`。未选牌时仍显示“先选牌”；选牌后提示“已选红相，再点按钮确认”，主按钮显示“打出红相”；提交期间显示“正在打出红相”。
3. 如果服务端快照、阶段或手牌变化使选择失效，沿用现有清理逻辑，牌名与按钮立即一起恢复为未选择状态，不能显示陈旧牌名。
4. 牌名缺失时保留兼容文案“出牌”，避免未来调用方只传布尔状态时出现空按钮。按钮尺寸和位置不变，不新增弹层，不允许双击牌面直接提交。
5. 屏幕阅读器从实时操作提示和按钮可访问名称中听到同一张牌；颜色信息使用完整中文牌名，不能只依赖牌面底色。

## 验收

- 667×375 和 568×320 下，选牌后操作坞同时出现准确牌名，按钮不换行、不越界。
- 单击、重复点击和双击只改变选择；只有点击“打出某牌”才提交。
- 服务端失败或新快照保留该牌时可以继续确认；牌已离手、阶段变化或断线时不保留陈旧名称。
- 客户端构建、服务端测试和完整 Playwright 回归通过，截图确认选中牌面与操作坞牌名一致。
