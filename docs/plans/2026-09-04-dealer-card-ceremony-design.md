# 本人庄标可见与定庄翻牌仪式设计

## 背景与实测

本人坐庄时，定庄牌虽然已经渲染在左下角本人信息卡的姓名行末尾，但 568×320 等窄画布中，该行会先被姓名和状态撑开，末尾的定庄牌再被容器 `overflow: hidden` 裁掉。结果只看见姓名或“庄”，看不见决定庄家的牌。

现有开局动画分为“定庄中”和“定庄牌”两段，但第一段只是一个文字胶囊，第二段直接出现正面牌并同时飞出“庄”字，缺少翻牌的因果顺序和视觉重点。

## 方案比较

### 方案 A：把定庄牌在中央长期再显示一份

容易看见，但会重新占用已经精简的中央牌桌，也会与座位旁的唯一庄家信息重复。

### 方案 B：只放大现有姓名行

桌面端简单，但极小屏本人信息栏宽度有限，随机长昵称仍会再次挤掉牌面，不能从结构上保证可见。

### 方案 C：为本人庄标与定庄牌保留固定尾部空间，并增强两阶段翻牌

采用此方案。本人姓名允许优先省略，庄标与定庄牌禁止收缩；定庄牌仍只常驻在唯一庄家座位旁。开局沿用服务端现有时序，先显示符合四色牌形制的红色细长牌背，再翻成真实牌面，最后显示“玩家名坐庄”并让庄标落向对应座位。

## 界面与行为

- 本人信息卡的身份行占满可用宽度；姓名作为可收缩区域，庄标和定庄牌作为固定尾部区域。无论本人昵称长度、是否显示回合状态，定庄牌都完整位于本人信息卡边界内。
- 其他三家继续在各自姓名旁显示唯一庄标和定庄牌；中央不增加常驻庄家信息。
- `DEALER_PICK` 阶段在牌桌中央显示暗红色、两头圆、细长的四色牌背，并提示“正在翻定庄牌”；不显示翻牌者姓名。
- `DEALER_CARD` 阶段在同一位置完成牌背到正面的短翻转，显示完整牌名和“某某坐庄”，随后金色“庄”标落到庄家座位。
- 整段沿用现有开局等待时间，不额外延后发牌或声明；动画不接管点击、不遮挡顶部控制栏。
- `prefers-reduced-motion: reduce` 下取消旋转、缩放和飞行动画，只用短淡入展示牌面与结果。
- 动画区域使用 `role=status` 与 `aria-live=polite`，读屏依次获得“正在翻定庄牌”和“定庄牌为…，…坐庄”；常驻庄家座位摘要仍保留同等信息。

## 验收

- 注入本人为庄家的确定性场景，断言本人信息卡内恰有一张定庄牌，牌面完整落在卡片边界内，庄标和牌面均未被昵称挤掉。
- 568×320、320×568 自动旋转、667×375 与 1280×720 均验证本人、左家、对家、右家坐庄时只有对应座位出现常驻庄家信息。
- 依次触发翻牌前和揭晓状态，验证红色细长牌背、正面牌、完整牌名、庄家结果与庄标落位顺序。
- 动画期间顶部控制栏和底部手牌不被覆盖；声明按钮仅在原有开局时序结束后开放。
- 减少动态偏好下没有 3D 翻转或飞行，信息仍完整可读。

## 非目标

- 不改变定庄算法、翻牌者、庄家手牌张数或服务端阶段时长。
- 不把定庄牌从庄家手牌中另建区域，也不在中央长期重复显示。
- 不因 iMac 使用 HTTP 改变正式 HTTPS 环境的浏览器能力策略；iMac 继续只承担降级路径和部署 smoke 验证。
