# 旧版手机视口兼容设计

## 问题

牌桌已经针对 568×320、320×568 自动旋转和现代动态视口做了精细布局，但页面根节点、旋转容器和少数弹层仍把 `dvh/dvw` 当作唯一尺寸来源。较老的 iOS Safari 不支持动态视口单位时会忽略整条声明，导致根节点没有确定高度、旋转后的宽高或偏移失效。低像素旧手机正是项目需要优先照顾的设备，不能因为浏览器版本较旧而退化成裁切或无法操作。

## 方案比较

1. 继续只支持 `dvh/dvw`：代码最少，但把旧设备排除在已经承诺的小屏体验之外。
2. 在每一条动态单位声明前手工重复一条 `vh/vw`：能覆盖旧浏览器，但散落在多个组件，新增弹层时容易再次漏掉，而且浏览器地址栏或软键盘变化时传统 `vh` 不够准确。
3. 由现有视口监听统一输出物理宽高像素变量，所有关键布局使用该变量，并在脚本加载前保留 `vh/vw` 后备：尺寸变化仍由同一监听更新，旋转和弹层共享一套来源，也能在现代浏览器继续使用实际动态尺寸。

采用方案 3。

## 设计

- `useResponsiveViewport` 继续监听 `resize`、`orientationchange` 与输入框相关的 `visualViewport` 变化，并额外向页面暴露物理 `viewportWidth`、`viewportHeight`。
- 根布局以内联 CSS 变量提供 `--physical-viewport-width/height` 的像素值；原有 `--effective-viewport-*` 在普通方向直接引用物理值，在自动旋转时交换宽高。
- 页面高度、旋转偏移、旋转容器和依赖全屏尺寸的弹层统一引用这些变量。
- `html/body/#app` 在 `100dvh` 前保留 `100vh`，保证 JavaScript 尚未执行或异常时仍有基本高度。
- 不改变小屏断点、牌面尺寸、自动旋转判定、服务端协议或玩家偏好。

## 验收

- 568×320 根布局计算变量准确为 `568px × 320px`；改成 320×568 后变量随物理视口更新，同时有效画布保持 `568×320`。
- 自动旋转后的根布局完整位于物理屏幕，顶部控制、声明、手牌、操作坞和弹层仍可达。
- 源码关键布局不再依赖单独的 `dvh/dvw` 声明；根节点保留传统单位后备。
- 667×375、1280×720 和现有全部 Playwright 行为不变。
