# 好友房准备状态回执设计

## 问题

好友房普通玩家的固定主按钮会在“我准备好了”和“取消准备”之间切换。当前点击只发送 `set_lobby_ready`，没有本地提交锁。慢网下连续点击会重复发送同一请求；本地服务较快时，第一次权威状态可能在第二次触摸前到达，第二次点击随即发送相反值，导致玩家以为已经准备，实际却又取消，房主始终无法开局。

## 方案

- `useRoom.setLobbyReady()` 返回消息是否交给当前 WebSocket。
- `App` 记录待确认的目标状态 `true / false`。第一次成功发送后立即锁住按钮，分别显示“正在准备…”或“正在取消准备…”，并提示“准备状态已发送，请稍候”。
- 本人权威 `lobbyReady` 等于目标值时完成提交；`lobby_error`、断线、换房、换座、离开等待阶段或个人退出立即清理。
- 8 秒没有权威变化时恢复按钮并提示“暂未确认准备状态，请再点一次”。
- 同一提交窗口内连续点击只发送第一条 `set_lobby_ready`，不允许准备与取消请求并发。

## 边界

- 只作用于好友房非房主真人；房主开始游戏、机器人和快速配桌没有准备按钮。
- 服务端准备规则、换座后自动取消准备和断线保留原选择的行为不变。
- 等待期间座位状态仍由服务端快照显示，不乐观地提前把“未准备”改成“已准备”。

## 验收

- 暂停 `set_lobby_ready` 时，568×320 主按钮保持原位、禁用并显示准确进度。
- 同一帧双击准备只积压一条 `true`；权威成功后才显示“取消准备”。
- 双击取消同样只积压一条 `false`；房主看到的座位状态与普通玩家按钮一致。
- 8 秒无确认后可重试，期间不影响离开房间或查看座位。
