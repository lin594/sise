# 好友房二维码邀请设计

## 背景

iMac 当前公开入口是普通 HTTP。系统分享和现代剪贴板在部分手机上要求安全上下文，已有兼容复制虽能兜底，但仍要求房主复制、切换聊天应用、找到联系人并粘贴。对当面同桌和不熟悉手机多任务操作的老年玩家，这条路径过长。

目标是在不依赖 HTTPS、第三方二维码服务或新增服务端协议的前提下，让另一台手机通过相机或微信扫码直接进入同一好友房。

## 方案比较

- 把二维码发送给外部图片服务：实现快，但会把私有房链接交给第三方，离线和内网也不可用，不采用。
- 手写二维码编码器：避免依赖，但纠错、字符编码和掩码实现容易出错，不适合邀请入口，不采用。
- 使用成熟的客户端二维码库在本机 Canvas 生成：链接不离开浏览器，HTTP 下也可用，可稳定控制尺寸、纠错和留白，采用。

## 交互设计

1. 好友房邀请卡保留原“邀请牌友 / 复制邀请链接”，旁边增加完整文字“出示二维码”。两个入口是并列方式，不互相替代。
2. 二维码弹层标题为“扫码加入好友房”，直接显示大尺寸黑白二维码、完整房间号以及“用微信或手机相机扫一扫”的一句说明。
3. 链接只在本机生成二维码，不请求远端图片服务；二维码内容与现有邀请链接完全一致，不包含 `playerToken` 或 `hostKey`。
4. 若二维码生成失败，弹层不空白，改为显示可长按选择的完整链接和清楚说明。已有复制入口继续可用。
5. Escape、遮罩和“关闭”均关闭弹层并把焦点还给“出示二维码”；Tab 不得离开弹层。读屏名称包含房间号，并说明二维码需要另一台设备扫描。
6. 568×320、667×375 和旋转后的 320×568 中，弹层完整位于有效画布；二维码保持正方形和足够留白，不因低高度被压扁。小屏采用左右结构，说明和关闭按钮在右、二维码在左。

## 实现

- 客户端引入 `qrcode` 及其类型，仅在打开弹层时绘制 Canvas。
- 新增 `FriendInviteQrDialog.vue`，自行管理绘制、生成失败、焦点约束和关闭。
- `App.vue` 统一生成无凭据邀请 URL，并管理弹层打开/关闭与焦点恢复；`LobbyPage.vue` 只发送“显示二维码”事件。
- 不修改服务端消息、房间身份或现有分享/复制降级链路。

## 验收

- HTTP 页面也始终出现“出示二维码”，打开后二维码可由另一设备识别为当前好友房 URL。
- 自动化解码 Canvas 结果或使用库的编码输入探针，证明二维码内容为无凭据邀请 URL。
- 568×320、667×375、320×568 和桌面弹层无溢出、无遮挡、按钮可触达。
- 生成失败时显示链接兜底；关闭后焦点回到入口。
- 客户端构建和完整 Playwright 回归通过。
