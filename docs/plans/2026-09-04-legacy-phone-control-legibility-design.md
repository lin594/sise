# 老旧手机控制可读性设计

## 审计结论

在 iMac 当前版本上用真实 Chrome 和 568×320 触控视口逐页测量后，主要牌面与核心动作已经达到既定尺寸，但仍有三处容易让老年玩家费力：玩法大厅的“本机临时档案”虽然整行可点，高度只有约 32px；顶部“查看规则 / 修改昵称”和牌局控制文字约 13.3–13.8px；手牌“前翻 / 后翻”在老旧横屏约 11.8px、高 34px。它们都不是牌局主按钮，却使用频繁，不能只因测试通过就继续维持偏小状态。此外，`GameBoard` 还重复接收了一次 `decision-key`，应顺手清除以避免模板歧义。

## 方案比较

1. 全局放大字体和所有按钮：覆盖最彻底，但会改变每个组件的继承尺寸，容易让 568×320 的座位、设置和操作坞重新重叠。
2. 把所有控制统一固定为 48px：触控宽裕，但忽略了用户已经确认“不死卡 48px”，也会挤压手牌首屏数量。
3. 按用途定向提高最低值：档案入口至少 40px；顶部文字至少 14px；翻看按钮保持 44px 以上宽度、提高到 36px 高和至少 13px 字。采用此方案。

## 行为与边界

改动只影响客户端样式和回归阈值，不改变协议、牌局规则或响应顺序。模式大厅仍需在 568×320 首屏完整显示三种玩法和开始按钮；手牌仍需首屏完整显示至少八张，前后翻与触摸横滑并存；320×568 自动旋转画布使用同一逻辑尺寸。档案摘要、规则、修改昵称和牌局顶栏都必须保持原有焦点、无障碍名称和单击语义。若定向放大仍造成溢出，应优先减少装饰间距，不能缩小牌字或隐藏核心操作。

## 验收

- 568×320 与 320×568 下，档案摘要高度至少 40px且最小可见文字至少 14px。
- 普通入口顶部按钮和牌局四个控制的文字至少 14px，现有触控边界不缩小。
- 手牌与声明的前后翻按钮高度至少 36px、可见文字至少 13px。
- 三种玩法、八张首屏手牌、设置面板和牌桌边界回归不退化。
