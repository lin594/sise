# 牌局浏览器返回保护设计

## 问题

手机浏览器的系统返回键和边缘返回手势很容易被误触。当前牌局虽然有清楚的“退出”按钮和二次确认，但浏览器返回不经过这条流程：玩家可能突然离开页面，随后又被本机凭证自动恢复，既不知道座位是否仍在，也容易误以为牌局已经退出。对不熟悉浏览器导航的老年玩家尤其困惑。

## 方案

进入好友房等待、声明、正式对局、结算或断线恢复后，在浏览器历史中放置一层仅属于当前页面的保护记录。玩家按系统返回时仍留在当前页面，并复用当前阶段已有的离房确认：

- 好友房等待阶段打开“离开当前好友房”确认；声明、对局和结算阶段打开顶部“退出”使用的确认。
- 如果设置、记录、规则、候选或其他模态层已经打开，第一次返回只关闭最上层内容，不再叠加退出确认。
- 取消退出后继续保留保护；确认退出则正常停止重连、清除凭证、离开连接并返回模式大厅。
- 主动点击页面内“退出 / 离开房间”、房间被解散或恢复失败时，也同步移除保护记录，避免返回大厅后还需要多按一次返回。
- 房间链接中的 `roomId`、`playerToken` 和 `new` 参数在移除保护后再次清理，不能因退回下层历史记录重新出现在地址栏。

不拦截刷新和关闭标签页。刷新已有可靠的原座断线恢复；浏览器原生离页提示在手机上不稳定、不能提供可读中文，并会妨碍这条恢复路径。

## 验收

- 对局中调用浏览器返回不会离开页面，而是打开与顶部退出按钮相同的确认层。
- 返回时已有设置层则仅关闭设置；第二次返回才打开退出确认。
- 取消确认后房间、手牌和连接不变；确认后进入模式大厅、凭证清除且不会自动重连。
- 页面按钮主动退出和房间端结束同样不会留下无效历史层或旧房间查询参数。
- 320×568 自动旋转画布中的确认层方向、边界、焦点约束和触控尺寸保持现有标准。
